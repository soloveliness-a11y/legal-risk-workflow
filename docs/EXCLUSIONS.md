# 发布范围规则（EXCLUSIONS）

> 本文件定义公开仓库的内容边界：公开仅保留通用方法、空白模板、独立构造并明确标注的示例，以及附有可核验出处的公开资料。
> 敏感与内部材料不应进入 git 历史；发现残留时按 [ROADMAP.md](./ROADMAP.md) 发布安全铁律处置（提交前用 `scripts/tools/release_scan.py` 扫描）。内部剔除台账与脱敏映射另行保存在仓库外的维护者私有档案，不随本仓库分发。

## 一、不入库内容

| 类别 | 说明 |
|------|------|
| 真实项目材料 | 真实报告、访谈纪要、案例笔记、逐项目回归报告——保存于维护者私有库；公开层只保留蒸馏后的通用方法与聚合评估（[EVALUATION.md](./EVALUATION.md)） |
| 机构内部范本与制度 | 交易文件范本、内部程序指引等——权属存疑且不具通用性；使用者自备范本接入（见 `templates/交易文件模板/README.md`） |
| 凭证与本地环境 | config.yaml、缓存、输出目录、本地安装元数据（.gitignore 约束；仓库只含 config.example.yaml） |
| 逐项目事实链 | 个案参数组合、访谈原话、内部谈判口径、投后结局——任何新增内容一律不得包含 |

## 二、新增公开内容的规则

- 不保留真实案例编号、来源映射、未公开状态和后验结局；也不采用"稳定编号 + 金额量级 + 年份"式的弱匿名化——数量、比例、期限按项目实际填列或留空
- 公开事件与实名公司仅作为行业参考保留，须附可核验出处（官方披露文件、报告期、链接）；不能核验出处时改用核查问题表述
- 每次新增前做跨文件组合复核：行业 + 轮次 + 时点 + 股权安排 + 事件 + 结局的组合即使去掉名称也可能识别到主体
- 关键词扫描清零只是辅助检查，不能替代人工组合复核

# 回归测试汇总（EVALUATION）

> 2026-09-17。本文件为公开发布层的唯一质量验证口径：逐项目的回归测试报告已转为维护者私有档案，
> 公开层只保留聚合结果，避免单项目特征被组合识别。

## 一、测试目的

在开源发布前后，验证重写后的技能系统在真实项目材料上不劣于原始交付版本（V7.3）：

1. 以历史真实交付报告为基准，度量风险发现的覆盖水平与误报水平；
2. 验证验收契约（AC1-AC5）与主检查点（CP1-CP4）在真实执行中确实阻断、确实生效；
3. 在技能重构、知识库扩充、反向优化三类变更后各安排回归，确认无劣化，并让新机制经受真实材料检验。

## 二、方法

- **忠实执行**：每轮均为全新会话代理，只拿到 SKILL.md + CONTRACT + 材料工作区，无任何开发上下文——模拟开源用户的真实体验。
- **基准隔离**：输入仅原始项目材料；历史交付报告、中间分析稿、加工版纪要全部隔离在输入集之外，事后才作为基准比对。
- **检查点真实性**：主检查点按真实"阻断—审批—放行"流程执行，非自动跳过。
- **判定口径**：基准发现逐项比对（完全覆盖 / 部分覆盖 / 整项遗漏）；基准之外的超覆盖产出逐条人工核验，无材料依据者计为误报。

## 三、测试场景（scenario class）

四轮回归对应四个 scenario class：

| 轮次 | scenario class |
|------|----------------|
| #1 | growth-stage |
| #2 | early-stage |
| #3 | pre-IPO |
| #4 | follow-on（对已投项目的后续轮次复检） |

四轮合计串起全部能力技能与完整链路（尽调启动 → 资料核查 → 报告 → 复核 → 交易文件审查 → 投后跟踪），其中后三轮为多技能管线串联的真实流转。

## 四、汇总指标

- **项目数**：4 个内部历史项目（对应上表四个 scenario class）
- **基准发现合计 54 项**：完整或部分覆盖 52 项；**整项遗漏 2 项**（均为低重要性，高优项零遗漏）
- **无依据发现（unsupported findings）：0**——评估产出的超覆盖项经逐条核验均有材料依据，且多批为基准报告未收录的真增量
- **验收机制拦截**：信息保真验收（关键实体/数字/日期交付前比对）累计拦截 5 处真实信息丢失
- **缺陷修复**：四轮累计修复约 64 项系统缺陷（类型见下节），全部随轮次同步修复并回归

## 五、系统缺陷类型

四轮回归暴露并修复的缺陷集中在流程与契约层，而非领域方法层，可归为五类：

1. **契约-实现漂移**：CONTRACT、技能正文、模板之间的编号、字段名与初始化时点口径不一致
2. **边界场景未定义**：清单零回复、含修订痕迹的协议、否定式表述、无实控人取数等场景原本依赖执行者合理延伸，后逐一明文化
3. **脚本解析容错**：金额带备注解析、否定语义误判等初筛脚本缺陷
4. **外部适配器纪律**：CLI 截断防护（先落盘再展示）、配额耗尽降级、曾用名/股改等主体变更场景补齐
5. **输出规范细节**：产出命名、矩阵口径、docx 标题映射等交付细节

## 六、未充分验证项

以下能力真实运行覆盖不足，相关结论应视为初步：

- **post-invest（投后检查）**：仅单次真实运行（交割文件 → 台账 → 预警主链路）
- **访谈多场综合**：多场访谈的综合验证有限，主要基于单场与书面回复形态
- **CLI 适配器**：仅一次真实采集实测，其余轮次走手工采集模式

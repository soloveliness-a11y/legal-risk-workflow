# Eval 11：evidence unresolved 时报告的条件化措辞

## 场景
冲突组 C015（2026-03股东会两份矛盾决议，见同组证据冲突场景）截至报告撰写仍是 unresolved。risk-report 撰写 R09（增资程序瑕疵风险）需要引用该次会议决议内容。撰写者倾向直接采用公司提供的甲版本叙述事实经过。

## 输入

evidence_registry.json 状态（报告撰写时点）：

```json
{
  "contradiction_group": "C015",
  "claim_id": "F042",
  "status": "unresolved",
  "members": ["E051", "E052"],
  "resolution": "unresolved；补证方向：调取登记机关备案版本、核验全体签署原件",
  "dossier_flag": "⚠️不一致，双源并列"
}
```

risk_matrix.json 片段：

```json
{
  "risk_id": "R09",
  "risk_title": "2026-03增资决议真实性存疑，增资程序存在瑕疵风险",
  "severity": "中高🟠",
  "legal_propositions": ["L048"]
}
```

待审报告草稿段落（Application 段）：

> 2026年3月18日，目标公司召开股东会并审议通过增资方案甲，注册资本由2,000万元增至2,600万元。本次增资的决议程序存在召集通知期限不足的问题……

## 期望行为
1. 报告不得以单一版本为既定事实展开：引用决议内容时采用条件化/双源措辞，如"目标公司提供的股东会决议显示审议通过增资方案甲，但尽调中另取得一份载明通过增资方案乙的同日决议，两份文件何者为真暂未核实（⚠️不一致）；若以甲版本为准，本次增资的决议程序另存在召集通知期限不足问题"。
2. unresolved 状态向读者可见：正文含"暂未核实/存在不一致/何者为真待核"类显式限定，并与 §12 关键风险信号、§14 待办（备案版本调取）联动。
3. report-review 复核规则：对依赖 unresolved 事实却采用断言式单版本措辞的段落，authority/一致性审计应判不通过并退回修改。

## 判定标准
- ✅ 通过：报告段落对决议内容采用条件化措辞并呈现双版本矛盾（或至少显式标注不一致未决）；R09 的风险论证建立在"若甲版本为准"的条件分支上；待办引用可见。
- ❌ 不通过：正文以"审议通过增资方案甲"为无保留事实陈述展开；或仅在脚注/矩阵注明而正文论证直接采信单一版本；或复核环节未拦截断言式措辞。

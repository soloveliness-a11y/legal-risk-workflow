## 判定标准核对（协议 §8）

- **C 相对 B**：重大问题识别不下降（B 漏 2 项，C 零漏）、判断可靠性上升、修改成本下降（2 处 vs 5 处）、确认/打断减少（0 次 vs 3 次）——成立。
- **C 相对 A**：按识别准确性、依据可靠性、建议有效性、修改成本判断，C 在可靠性与修改成本两项胜出，识别与建议两项相当（各有所长）；A 的两处实质缺陷（定级失当、未证交易事实）恰是"线索不等于成立"评审规则针对的类型——成立，且胜在内容而非格式（评审人被明确告知不以格式加分）。

## 局限

1. 单组材料（成长期/芯片设计/2 份材料）单次运行；结论不外推到其他轮次与行业，组 2（Pre-IPO 制造业，含结论性缺口与多来源冲突）待补。
2. 评审为机器预审（评审模型与执行模型同族）；终审建议人工盲评——去标识评审包保留在运行档案，人工评审人可直接使用。
3. B 臂"行业数字不可溯源"的判定有评审包口径因素：B 的研究底稿（sources_industry.json 等）存在于其工作区但未随报告附入评审包。双面性：投委会读者拿到的确实只有报告本体，该判定在"读者视角"下成立；但在"底稿可查"口径下 B 的引用有落盘来源。此点不计入 B 的排名扣分依据，如实记录。
4. 测试审批人由主持者（AI）担任，审批措辞按 B 臂自己呈报的选项作出，未向任何执行者泄露评审标准。
5. A 臂 40 项待核实的"高"档密度问题与 B/C 的清单组织差异，部分反映裸模型缺乏清单分层惯例，属行为差异记录，非否决项。

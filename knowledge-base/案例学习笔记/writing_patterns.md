# 风控报告跨案例写作模式

> 本文件为写作方法参考：不保留可回溯到单一标的的编号或事实组合。
> 汇总法律风控实践中常见的报告结构、分析方式与表达模式，供 risk-report Skill 撰写报告时参考。

**结构说明：** 本文件按使用场景分四大板块——
- **Block A（§1-§4）**：风险分析方法论——风险识别和重点问题分析时参照
- **Block B（§5-§9）**：报告结构与写作风格——逐章撰写时参照
- **Block C（§10-§11）**：特定版本规范——投委会版/天使项目转写时参照
- **Block D（§12）**：跨作者共性 vs 风格选项——判别某写法属全组规范还是作者风格选项时参照

---

# Block A：风险分析方法论

---

## 一、风险判断模式

### 1.1 风险等级与矩阵条目

不设等级分布先验：评级逐项依据证据与评级原则（risk-report references），不从"多数项目如何"出发。矩阵条目数由识别结果决定——先完整识别全部重大风险，再仅为可读性合并同类项；同类风险可合并表述，禁止为凑数量拆分或压低问题。二轮报告矩阵仅列增量/未解决项（亦有以叙述型总结收尾、不设矩阵的先例，借鉴时应补矩阵）；天使项目正文可不设矩阵汇总表但 risk_matrix.json 仍必产（CONTRACT AC2）。数量仅在输出摘要中呈现，不作为识别阶段的约束。

### 1.2 上调为"高"的触发条件

需满足多因素叠加：

| 触发因素 | 典型表现 |
|---------|---------|
| 财务真实性存疑 | 壳公司+关联蛛网+资金流向异常 |
| 独立性严重缺陷 | 大企业分拆四维度均有瑕疵 |
| 制裁/关税实质影响 | "关联实体"受制裁或关税实质影响收入成本 |
| 税务金额重大 | 补税金额重大并伴随高新资质撤销风险 |
| 多轮回购集中触发 | 多轮到期日集中在短期 |
| 核心IP归属存疑 | 高校职务发明+配偶代持 |
| 业绩对赌踩线 | 仅小幅超出，审计调整可触发 |

### 1.3 下调风险的条件

- 有明确整改路径且时间表清晰
- 有同行先例可参照（如竞业限制三维度论证"被实质追究的风险较低"的写法）
- 已签署确认函/和解协议
- "系拟上市企业常见不合规事项"定性

## 二、高频分析框架

### 2.1 六种核心框架

| 框架 | 适用场景 | 展开要点 |
|------|---------|---------|
| 四维度矩阵式 | 关联交易/独立性 | 研发×采购×资金×人员 × 历史/现存/未来 |
| 三段式论证 | 无实控人/控制权 | 现状→法律分析→后续计划+时间线 |
| 定量→定性→建议 | 税务/财务风险 | 补税金额→税率差影响→风控提示 |
| 逐条摘录→评价 | 投资方案保障条款 | 条款原文→逐条分析→保障力度评价 |
| 趋势→阈值→预判 | 关联交易趋势 | 当前占比较高+业绩承诺→可能突破30%审核线 |
| 双向论证+差异点 | 关联方认定争议 | 正方理由+反方理由+本公司差异点 |

### 2.2 特殊场景分析模板

| 场景 | 推荐分析框架 |
|------|------------|
| 大企业分拆独立性 | 四维度(研发/采购/资金/人员) × 三时态(历史/现存/未来) |
| 无实控人论证 | 现状→法律分析(IPO规则+案例)→后续计划+时间线 |
| 海外专利诉讼 | 涉诉专利表→逐案追踪表→三重费用测算→市场退出评估→FTO验证 |
| 关联方蛛网穿透 | 工商信息四维度+关联线索四维度交叉比对矩阵 |
| 港股18C上市 | 条件对照表(7-9维度)逐一核对 |
| 高校教授创业 | 兼职审批+持股代持+职务发明+科技成果转化四维 |
| 客户-供应商重叠 | 收入占比+供应链依赖+回款风险三维度 |
| 关税/贸易政策 | 关税现状→应对措施→客户关系→整合执行风险 |
| 委外研发/销售费用 | 客户-推广商对照表+受托方工商穿透 |
| 境外运营 | 三种模式(合资/自建/外协)对比+选址尽调+失败案例 |
| 可转债投资 | 股权未清理完成时替代直接增资 |
| 二轮前次追踪 | 追踪表(序号/事项/前次情况/最新进展/是否解决) |
| 业绩对赌踩线 | 冗余空间量化+审计调整风险+第三方审计复核建议 |
| 算力/AI业务资质 | 业务模式三层拆分→资质需求逐层分析 |
| 产业基金特殊权利 | 折价认购权量化分析(订单占比→估值折扣→稀释影响) |

## 三、建议力度与提示措辞

### 3.1 风险等级→建议力度对应

| 风险等级 | 建议层次 | 措辞模板 |
|---------|---------|---------|
| 高🔴 | 交割前提 / 可转债 | "建议将XX作为交割先决条件"、"建议以可转债方式投资" |
| 中高🟠 | 交割后承诺 + 具体时间表 | "建议在交易文件中约定交割后XX个月内完成" |
| 中🟡 | 陈述与保证 | "建议在陈述与保证中明确…" |
| 中低🔵 | 投后跟踪 | "建议投后持续关注…" |
| 低🟢 | 备忘记录 | "提请投资人注意" |

### 3.2 风险类型→建议层次对应

| 风险类型 | 推荐层次 | 逻辑 |
|---------|---------|------|
| 财务真实性存疑 | 可转债+专项审计 | 不直接增资，先以债进入，待清理完成再转股 |
| 核心IP无书面确认 | 交割前提 | 不解决不投资 |
| 代持未解除 | 交割前提或陈保 | 影响股权清晰性 |
| 资质即将到期 | 投后承诺 | 非阻塞性问题 |
| 历史沿革与工商不一致 | 陈保+双重确认 | 要求创始人和管理层双重陈保 |
| 竞业限制/前雇主IP | 陈保+FTO | 陈保兜底+建议做FTO排查 |
| 关联交易依赖 | 投后持续跟踪+承诺清理 | 非一朝一夕能解决 |

### 3.3 常用句式

| 类型 | 示例 | 适用场景 |
|------|------|---------|
| 审慎定调 | "受限于专业知识和尽调手段，无法完全排除" | IP风险/专业判断边界 |
| 辩证评价 | "业务板块多元、持牌众多既是竞争壁垒，也是负担" | 利弊并存的风险 |
| 常见定性 | "系拟上市企业常见的不合规事项" | 运营合规瑕疵 |
| 合理怀疑 | "基于线索的合理怀疑，最终确认有待专项审计" | 证据不足时的财务风险 |
| 时效标注 | "截至2025年X月X日的…" | 引用信息时效性 |
| 交叉验证 | "我们查阅了…公开报道，暂未发现…" | 与访谈信息交叉 |
| 递进肯定 | "已取得试点许可"+"但规模化所需资质仍在申请"+"跨境架构待检验" | 天使/跨境项目风险分层 |
| 结论归因辨析 | "本项目**不属于该情形**（存在否决级高风险且可缓释），故结论为…而非三选项之一。但需向投委会明示：…若上述条件在合理期限内仍不交付，本项目将转化为'风险可解释但无收敛路径'情形，届时应重新上会评估" | 结论归因三选项的强制二选一豁免论证：先排除适用、再明示转化条件，防止"非此即彼"误用与结论静态化 |
| 追踪表三段式收尾 | "{跟踪事项数}项中{闭环数}项已解决，{恶化事项}待处理；共性根因为{可由证据支持的原因归纳}，对应动作{逐项列明}" | 二轮前次追踪表的收尾段：闭环率→恶化点名→根因归并，把散项收束成可决策结论 |
| 对价-信息义务反差 | "公司对'有对价的合同义务'（里程碑/迁址）履约记录良好，与'无对价的信息义务'（清单回复/年审）形成反差，提示谈判中应将信息义务与对价机制挂钩" | 配合度类风险（非独立法律风险）的论证与转化：从履约记录分化推导谈判策略，避免仅停留在"配合度差"的抱怨式表述 |

## 四、法律风控视角与财务视角的区分

> 核心原则：**财务数据是引子，法律后果才是分析对象。**

### 4.1 问题识别

风控报告中常出现的"财务风险与客户集中度"章节，容易写成财务尽调报告的压缩版——堆砌应收账款账龄表、毛利率对比、银行授信明细、营收波动统计。这些内容：

- 与财务风控报告高度重叠，投委会会看到两份雷同报告
- 缺乏法律风控的独特价值——法律风控应该回答的是"这些财务状况会引发什么法律后果"

### 4.2 转换原则

| 维度 | 财务视角（应避免） | 法律视角（应采用） |
|------|-------------------|-------------------|
| 数据使用 | 详细列表（账龄表、客户排名、银行授信） | 一句话引出关键数字，重点放在法律后果 |
| 分析方向 | 偿债能力、盈利能力、现金流 | 合同权利保护、连锁法律风险、IPO合规 |
| 核心问题 | "财务指标是否健康？" | "财务状况引发了哪些法律风险？" |
| 典型子问题 | 应收周转率、毛利率异常 | CoC条款未核查、回购执行不确定性、收入确认合规 |

### 4.3 财务→法律的传导链模板

```
财务状况（背景）→ 法律风险分析（核心）→ 交易文件建议（落点）

示例（应收账款）：
财务背景：应收账款规模大（同比增长显著），1年以上账龄占比高（数字按项目实际填列）
   ↓ 传导
法律风险：合同付款条款是否完备？逾期利息和违约金是否约定？
   ↓ 进一步
连锁法律风险：如某主要客户融资失败，公司是否有担保权益？
   ↓ 落点
交易文件建议：在陈述与保证中确认主要客户合同不包含CoC条款
```

### 4.4 财务相关章节的法律风险分析模板

1. **重大客户合同风险敞口不明**（尽调缺口）：前N大客户合同未取得→CoC/排他/终止权无法评估
2. **应收账款的法律保障不足**：付款条款/违约救济/担保权益
3. **流动性紧张的连锁法律风险**：回购权执行/银行贷款CoC/交叉违约/质押处置
4. **收入确认合规与IPO影响**：交付vs验收/签章规范/函证实操
5. **关联交易定价公允性**：毛利率异常→利益转移→IPO审核风险

> **砍掉的内容**：应收账款账龄详表、各业务线毛利率对比表、银行授信明细表、供应商集中度排名表、营收波动统计表——这些让财务风控去写。

## 五、报告格式选择

| 项目特征 | 推荐格式 | 典型篇幅 |
|---------|---------|---------|
| 天使/种子轮 | 核查清单（10项三列表格） | ~4000字 |
| 早期/首轮 | 简化版标准报告（可无风险矩阵） | 8-15页 |
| 成长期首轮 | 标准8章报告 | 15-30页 |
| Pre-IPO首轮 | 标准8章 + 上市路径分析章节 | 20-35页 |
| 二轮/追加 | 二轮追踪报告（前次追踪表 + 增量分析） | 首轮的1/2~等长 |
| 跨境/多司法管辖区 | 标准8章 + 监管风险独立成章 | 20-35页 |

**标准8章核心架构：**
前提说明 → 基本情况（股权架构/创始团队/历史沿革/ESOP）→ 行业监管政策（可选）→ 重点问题分析（4-7个主题）→ 投资方案评价 → 其他关注事项（中低风险表格化）→ 风险总结 → 附件

---

## 六、重点问题标准结构

```
每个重点问题按以下结构展开（IRAC变体）：
1. 事实呈现（数据/表格/引用）
2. 法律分析（法规依据/案例对比）
3. 风险评估（等级+量化影响）
4. 风控建议（交割前提/陈保/投后承诺 三选一或组合）
5. 交易文件衔接（"建议在交易文件中约定…"）
```

**中低风险事项** 不展开四段式，统一放入"其他关注事项"表格：

| 关注事项 | 情况说明 | 风险等级 |
|---------|---------|---------|
| （示例）物业租赁备案 | 未办理备案登记，实际使用无争议 | 中低🔵 |

> 规则：中低🔵或低🟢不展开，表格化处理。中🟡及以上必须在正文展开四段式。

## 七、写作风格与章节过渡

### 7.1 八条核心规则

1. **表格替代长段文字**：历史沿革、风险矩阵、关联交易、资质状态等优先表格化
2. **定量优于定性**：凡能量化的必须量化（金额/比例/时间线/冗余空间）
3. **法规引用精确**：到条款号/国标号/案例名称
4. **审慎但不越界**：用"无法完全排除"替代"存在风险"，区分"合理怀疑"与"确认事实"
5. **建议直接衔接交易文件**：每条建议后跟"在交易文件中约定/作为交割前提/在陈保中明确"
6. **辩证视角**：既提示风险，也承认缓释措施的有效性（"即使…也极有可能…"）
7. **时效性标注**：引用信息标注截至日期
8. **二轮报告特征**：前次风险追踪表是标志性结构，仅增量/未解决事项展开分析

### 7.2 章节过渡方式

1. **表格化过渡**：用表格替代文字过渡（"其他关注事项"三列表格、风险矩阵表）
2. **数字编号衔接**：重点问题用编号（一、二、三…）串联，每项内部再用子编号
3. **前次→当前对照**：二轮报告用追踪表（前次情况/当前情况/当前状态）
4. **"风控提示"固定段落**：每个重点问题末尾统一用"风控提示"或"风控建议"段落收束
5. **结论段二分法**：报告末尾用二分法总结（如"历史包袱"+"新业务政策风险"的二分收尾）

## 十、投委会版规范

> 适用时机：底稿版（V0.xd 或 V1.0）已完成且内容稳定，用户要求转写投委会版时。

### 10.1 两段式替代四段式

| | V0.1d底稿版（四段式） | V1.0投委会版（两段式） |
|---|---|---|
| 结构 | 事实背景→法律分析→风险评估→风控建议 | 综合分析与风险判断→风控提示 |
| 用途 | 内部底稿/知识库，风险点全覆盖、细节全保留 | 投委会正式汇报，精炼但无信息损失 |
| 关系 | 保留为base版本，后续改动有参照 | 基于底稿版改写，不省略关键事实和风险分析过程 |

**核心原则：消除重复，而非压缩内容。** 四段式中同一事实在"事实背景""法律分析""风险评估"中反复出现的部分，融合后只说一次，一次到位。

### 10.2 综合分析的三种叙事推进方式

按问题复杂度选用：

| 模式 | 适用场景 | 推进逻辑 | 示例推进链 |
|------|---------|---------|---------|
| **递进式** | 因果链清晰的问题 | 事实A→分析A→引出事实B→分析B→风险判断 | IPO路径→突击入股→锁定期；业务模式→资质→收入确认→税率 |
| **分层式** | 多维度/多层面的问题 | 按维度分小节，每节内事实+分析+判断一体 | 技术独立→人员独立→业务独立；IP归属→人员→资金→关联交易 |
| **论证式** | 需要可行性评估的问题 | 现状→问题→可行性分析→风险判断 | 关税现状→规避方案→可行性→风险；持牌现状→竞争→合规成本 |

**关键约束：** 不论哪种模式，每个风险点的风险等级标注仍在标题行（如"风险等级：🟠中高"），保持可扫读性。

### 10.3 融合叙事核心技法

**技法1：数据即分析（最重要）**

将数据事实与影响判断融为一句，不再分两次说：

- ❌ 四段式："{连带责任金额}"（事实背景）→ "该等金额超过年净利润，存在资金压力"（风险评估）
- ✅ 融合式："{连带金额}，超过年净利润（约{倍数}倍），存在一定资金压力"（数字按项目实际填列）

**规则：凡能量化的影响（占比/倍数/安全垫），紧接数据后直接给出判断。**

**技法2：表格后紧接判断**

- ❌ 表格→隔了一个"法律分析"段→结论
- ✅ 表格→紧接一句话判断

**技法3：事实带分析、分析引判断**

- ❌ 先堆完所有事实再统一分析
- ✅ 事实1+分析1→引出事实2+分析2→综合风险判断

**技法4：辩证收束**

风险判断结尾常用辩证句式，既提示风险也承认缓释：
- "理解在交易所层面受理没有实质障碍，但证监会能否最终批准仍存在较大不确定性"
- "业务板块多元、持牌众多既是竞争壁垒，也是负担"

### 10.4 底稿版 vs 投委会版差异总表

| 维度 | 底稿版 | 投委会版 |
|------|--------|---------|
| 重点问题 | 四段式（事实→法规→分析→建议） | 两段式（综合分析→风控提示） |
| 风控提示粒度 | 指定条款类型+具体内容 | 给方向+关键约束（1-3条） |
| 素材依据 | 详细表格，逐项标注✅/⚠️/❌ | 一段话概括主要依赖资料类型 |
| 财务指标 | 多年对比详表 | 关键数字融入正文叙述 |
| 客户/供应商 | 完整排名表 | 仅引述关键占比 |
| 风险矩阵 | 完整矩阵表（篇幅参考，非数量配额） | 精简矩阵（核心项） |
| 综合评估矩阵 | 4维度表格 | 简化为2列（维度+结论） |
| 保护条款 | 逐条展开 | 4方向（先决条件/交割后承诺/陈述保证/赔偿）必须全部出现 |
| 正文中的表格 | 大量 | 能用叙述替代的尽量不列表 |
| 条款映射 | 含"交易文件衔接提示"段落 | 无，映射关系留在底稿版 |

**三类风控提示模板（投委会版）：**

| 风险等级 | 力度 | 措辞示例 |
|---------|------|---------|
| 高🔴 | 交割前提/可转债建议 | "建议将XX作为交割先决条件" |
| 中🟡 | 交割后承诺/陈保方向 | "建议在交易文件中约定交割后XX月内完成" |
| 中低🔵/低🟢 | 持续关注/备忘 | "建议投后持续关注XX进展" |

### 10.5 逐章转写守则

> 来源：投委会版转写的常见错误归纳。
> **本节在每次底稿→投委会版转写前必须逐条确认。**

#### A. 总则

| # | 规则 | 说明 | 反例（禁止） |
|---|------|------|-----------|
| G1 | **从底稿原版重新转写** | 每次投委会版都从底稿版原文转写，不在前次投委会版上修改 | 在被否的投委会版上打补丁 |
| G2 | **"消除重复"≠"省略内容"** | 同一事实在四段式中反复出现→融合后只说一次，但**所有事实和判断都必须保留** | 删掉某个维度的分析 |
| G3 | **引用时必须内联结论** | 凡涉及"详见X节"的，必须在当下段落把结论说出来 | "已在3.3节详述，此处不赘述" |
| G4 | **财务数据必须多年对比** | 涉及趋势判断的财务指标，至少列2-3年数据横向对比 | 只列最近一年数据 |
| G5 | **不做全文一律简化** | "简化"仅适用于素材依据。其他章节根据逐章规则差异化处理 | 把基本情况/其他关注事项/正面因素一律压缩 |

#### B. 逐章规则

| 章节 | 转写规则 | LLM常见错误（禁止） |
|------|---------|-------------------|
| **一、报告前提** | 素材依据合并为1-2段叙述（合并同类项）。初稿先行声明保留底稿原文 | 素材依据逐项列表 |
| **二、基本情况** | **保持底稿原样**，不删减不压缩 | 压缩股权表/沿革表/治理表 |
| **三、重点问题** | 核心章节，两段式融合叙事。**"综合分析"需比底稿更丰满**。跨节引用→内联结论(G3)；财务→多年对比(G4) | 压缩过度导致逻辑链缺失 |
| **四、投资方案** | 投资方案概要：未出则跳过。保护条款：4个方向全部出现（先决条件/交割后承诺/陈述保证/赔偿）。每个方向列核心要点 | 删除某个方向导致总结自相矛盾 |
| **五、风险矩阵+总结** | 矩阵保留（可简化列）。总结含三部分：（一）总体判断 + **（二）正面因素** + （三）投资建议 | 删掉正面因素 |
| **六、收尾** | 落款 + 版本说明（注明投委会版与底稿版差异仅在表述精炼度） | 遗漏版本说明 |

#### C. 自检清单（投委会版写完后自动执行）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| Q1 | Part二信息等价性 | 所有表格行数、关键数值与底稿一致 |
| Q2 | 跨节引用内联结论 | 全文搜索"不赘述""详见""见上文"，每个后200字内有结论陈述 |
| Q3 | 财务数据多年对比 | 3.6节所有财务指标表≥2个年度列 |
| Q4 | 保护条款4方向齐全 | 先决条件+交割后承诺+陈述保证+赔偿条款全部出现 |
| Q5 | 总结引用与正文一致 | 总结段提到的方向与Part四实际包含的方向完全对应 |
| Q6 | 正面因素保留 | Part五含"正面因素"独立段落 |
| Q7 | 风险等级一致 | 逐一核对R编号等级与底稿无变动 |
| Q8 | 待补标注保留 | 底稿中所有【待补·Pxxx】在投委会版中均存在 |

### 10.6 两版并行的产出流程

```
dd-prep + dd-check + dd-interview
        ↓
  risk-report V0.1d（四段式底稿）
  - 全展开，风控建议逐条映射交易文件条款
  - 作为后续修改的base版本
        ↓
  report-review → 修订 → 定稿 V1.0
        ↓
  risk-report V1.0（两段式投委会版）
  - 综合分析与风险判断：融合叙事，消除重复
  - 风控提示：方向性建议，不逐条指定条款
  - 中低风险表格保持不变
        ↓
  txn-docs → 从V0.1d底稿取具体条款映射
```

### 10.7 融合叙事的禁止事项

1. **禁止过度压缩**：融合不是省略。关键事实、量化数据、法规引用必须保留
2. **禁止省略分析过程**：风险判断的逻辑链必须完整，不能只给结论
3. **禁止模糊风险等级**：融合后风险等级标注不可省略
4. **禁止风控提示空洞**：每条建议必须包含明确的动作方向
5. **禁止两版信息不一致**：V1.0的风险等级、关键事实、风控方向必须与V0.1d一致

## 十一、天使项目精校标准

> 来源：天使/早期项目核查清单的写作实践归纳。
> **本节作为AI撰写天使项目核查清单时的风格参照。**

### 11.1 结构与格式

| 维度 | 规范 | 原因 |
|------|------|------|
| 标题 | 加粗（非`###`heading），如`**2.1 商业模式的合法性**` | 精校后改用加粗，保持与正文视觉统一 |
| 节间分隔 | `---`分隔线 | 10节核查项间用分隔线隔开 |
| 表格列名 | 加粗（如`**核查项**`） | Word渲染更醒目 |
| 落款 | 右对齐，写真实姓名 | 撰稿人/复核人需填真实姓名 |
| 免责声明 | 精校版删除 | Word版自行判断是否保留 |

### 11.2 措辞审慎度

| AI原版 | 精校版 | 学习点 |
|--------|--------|--------|
| "充分缓释" | "实质性缓释" | 天使项目风险不确定性大，措辞不宜过于肯定 |
| "该确认削弱了法律基础" | "该确认可作为不利反证" | 法律表述更精确 |

### 11.3 信息精简

| 删除内容 | 原因 |
|---------|------|
| 表格中✅❌标记 | Word中emoji显示异常 |
| 非关键个人信息（如月薪细节） | 天使项目非关键信息，精简 |
| "实际出货情况尚待核实" | 公司已提供信息，不再标注未核实 |
| 风控提示后的独立免责声明段 | 已在报告头部说明 |

### 11.4 结论结构

天使项目结论采用两段式：
1. **（一）核查结论**：总结主要风险及缓释情况，一句"未发现实质性障碍"
2. **（二）投后关注提示**：列出交割后承诺事项（3项以内）

## 十二、跨作者共性 vs 风格选项

> 来源：跨作者写作实践的对照归纳，用于区分共性规范与作者风格选项；不涉及具体样本信息。
> 判别标准：跨作者稳定出现、与作者个人偏好无关的写法 → **共性规范**（新报告必须遵循）；依赖特定条件或体现作者判断风格的 → **风格选项**（可选用，但须遵守使用纪律）。

### 12.1 共性规范（跨作者稳定，固化为必做）

| # | 规范 | 操作要点 |
|---|------|---------|
| N1 | **风险→条款一一映射收尾** | 每项风险最终落到交割先决条件 / 交割后承诺 / 回购触发 / 陈述与保证 / 特殊赔偿之一，多数风险以此三类收尾；无条款落点的风险视为分析未完成。给出条款修改方案优于仅提示（有针对回购触发条款表述缺陷直接给出改法的先例，也有把无法书面化的订单承诺转化为业绩对赌的先例） |
| N2 | **自建定量测算优于定性描述** | 可直接复用的五类测算模板：牌照增量按官方三套方法分省自算；侵权赔偿按获利倍数/许可费倍数/法定上限分档测算；社保敞口逐年测算；创始人现金流三张表——实缴义务+股权款尾款+回购能力叠加；对赌赔付公式按多档完成率代入 |
| N3 | **公开信息四层交叉验证** | ① 上市公司定增问询答复/审核问询回复 ② 招股书与同业上市披露 ③ 过会样本+被否样本双向对比 ④ 监管电话咨询且留痕（含咨询电话号码）写入报告。无第三方尽调时，问询函即监管版尽调清单 |
| N4 | **落款日期与内容时间线交叉核对** | 多版迭代（大预审→投委会版）时，终稿落款日期须与访谈时间、所引尽调报告日期、投委会材料时间互核；落款年份笔误即曾由此类矛盾暴露——低成本高收益的强制复核点 |

### 12.2 风格选项（可选用，附使用纪律）

| # | 选项 | 使用纪律 |
|---|------|---------|
| S1 | **强硬判断表述**（"合理怀疑存在代持""股权架构可能不真实"级直言；直接推翻投资建议书时间表；法律风控报告罕见地对投资价值本身保留意见） | 仅在多项独立证据叠加时使用（可叠加的独立证据类型示例：核心人员背景与核心IP来源不一致、核心研发高度依赖外部方、专利由关联方代持等——多类独立线索同时出现才直言）；措辞强度与证据强度挂钩。注意：强硬判断风格的"高"定级具有实质否决权重，非例行标注——报告的风险等级须结合判定标准与结论阅读，不可当作常规保守措辞打折 |
| S2 | **风险矩阵形态按报告版本分层理解** | 形态差异是规范演进：早期样本以文字型风险总结收尾（天使项目另有豁免），其后矩阵渐成标准形态。引用早期框架时按现行规范补矩阵（§1.1）；后期报告仍可不设矩阵的合规情形限于天使/早期简化版（见§五格式选择） |

### 12.3 与既有章节的关系

- N1 与 §3.1/§3.2（风险等级→建议力度）、§六第5步（交易文件衔接）同源，本节将其升格为跨作者验证的硬规范；
- N2 是 §7.1 规则2（定量优于定性）的展开，补充五类可复用测算模板的出处；
- N3 与 §3.3 句式表"交叉验证"条目互补，给出四层公开信息源清单；
- N4 是 §10.5 版本管理纪律的补充（底稿版→投委会版多轮迭代场景）；
- S1 与 §7.1 规则4（审慎但不越界）不冲突：审慎是默认档，强硬是证据充分时的例外档。

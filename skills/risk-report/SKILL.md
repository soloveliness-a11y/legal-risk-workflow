## 2. 报告格式适配（阶段决策）

| 投资阶段 | 报告格式 | 章节结构 |
|---------|---------|---------|
| 天使/Pre-A | **核查清单格式** | 项目概况 + 核查结果（N 项表格，典型 10 项左右）+ 核查结论 |
| A 轮及以后 | **标准 8 章格式** | 封面→开场白→前提→基本情况→重点问题→投资方案→风险总结→落款 |

> 核查清单格式的风险分析**仍遵循 IRAC 四段式**，只是不按章节展开，改为逐项表格 + 分析。产出命名 `{公司名}-法律风控核查清单-V{版本}d-{日期}.md`；天使模式同样必产 risk_matrix.json（CONTRACT AC2 不因格式豁免，正文可不设矩阵汇总表）。
> 格式决策在启动时做出并写入 `project_log.md` 一行。

## 3. 预检（Step 3.0）

> Dossier 是主信息源（canonical working view），散落文件是补充。**读取顺序**：Dossier → verification_table.json → 原始文件。注意：这只是检索与初始参考顺序，**不是冲突裁决顺序**——来源不一致时按 CONTRACT §2.5 三不变量与 evidence_resolution_framework 六维裁决，不得以读取先后定胜负。

1. 全量读取 `project_dossier.md`：§0 元信息 → §1-§10（公司事实）→ §12（风险信号）→ §13（完备度）→ §14（待办）
2. 对照 §13+§14 识别信息缺口；Dossier 缺失的维度从散落文件（qcc_cache / research / 核查表 / 访谈纪要）补充
3. 工商数据复查：qcc_cache 距上次查询 >7 天则触发复查 + diff 回填（CONTRACT §7.1）
4. 向用户展示：已获取的核心信息摘要 + 信息缺口清单 + 预判风险等级分布

## 4. 风险识别（撰写前必经，最耗时的核心环节）

> 主 CP 有条件通过（如 CP2 附"V0.xd 先出稿"条件）可豁免本技能的下游触发前提（如模块 B 未执行）；豁免与所附条件必须在报告前提说明中显式写出。

### 步骤 1：通读全部素材
逐一阅读所有素材，重点：外部律所/会所报告的风险提示、访谈关注要点、投资建议书交易结构。
**扫描件必须先读出文字**（外部尽调报告、投资建议书、工商档案/证照、访谈纪要 PDF 等典型扫描件；先试读，扫描件才 OCR，CONTRACT §7.2；合同/员工花名册/财务报表等敏感类别禁止外传 OCR，走本地/人工/AC5 降级）——未读出文字将导致风险识别严重遗漏。

### 步骤 2：识别潜在风险点
不限于 17 大类体系，从素材中全面识别：外部报告已指出的、访谈中发现但外部报告未覆盖的、行业研究中发现的监管趋势。每个风险点标注：来源素材、涉及大类、初步风险等级。

### 步骤 3：按项目实际情况组织分析框架
17 大类 55+ 子类是**参考框架，不是必填模板**——具体项目可能只涉及 8-10 个大类，也可能有体系外风险点。合并关联风险点，避免重复分析。
> 17 大类参考框架：[`knowledge-base/reference/risk_classification_framework.md`](../../knowledge-base/reference/risk_classification_framework.md)

### 步骤 4：向用户展示分析框架，**确认后才开始撰写**（V0.xd 先出稿模式下可后置：框架确认随初稿一并呈报 CP3，不阻断生成）
展示：风险点清单 + 建议分析框架。用户可增减风险点、调整分类、修改重点。
确认结果写入 `project_log.md` 一行（风险点编号与标题、预判等级分布、信息缺口数、确认人=审批人）。

### 步骤 5：法律依据核验
对涉及法律义务、监管要求或上市规则等规范性判断的风险项，调用 legal-research（CONTRACT §7.5）核验条文现行有效性；产出 authority_record（落盘 `legal_authority.json`）并通过风险项 `legal_propositions` 字段关联（L 编号）。纯交易执行/事实核查/商业依赖类风险不核验、不设置该字段。

## 6. 生成策略：按风险主题聚焦，产物形态灵活

**核心价值是聚焦思考**：第五章（重点问题）每个风险主题独立生成 IRAC 分析，不混合思考——类似审计逐科目审查，比一口气分析所有问题更精准。

**产物形态自选（均已验证可行）：**
- **常规项目**：整篇报告一次成稿（存量项目全部由此路径产出，含 6.9 万字无截断报告，是已验证兜底路径）
- **长报告**：可按章分批生成后串联（如 Ch.1-3 / Ch.4 / Ch.5 按主题分批 / Ch.6-7）；产物允许合并为单文件，`report_ch*.md` 分章落盘是可选手段而非强制要求
- 单批内容过长时可再拆子节分批生成，合并后统一格式

**通用纪律（无论整篇还是分章）：**
- **信息保真**：事实只从 Dossier（及其可回溯的源文件与证据链）取，不从模型记忆取；论述只允许引用已记录的事实，不凭记忆发挥。`📌待核实`/`[推断]` 项在报告中写为"待核实"/"存在…的可能性"，不得当断言
- 每章聚焦当前章节所需事实即可，无强制限定 Dossier 读取节
- 全部 Markdown 写完后一次性转 docx，**严禁分段生成 Word 再拼接**

## 7. 报告结构（标准 8 章）与篇幅配比

| 章节 | 篇幅 | 占比 |
|------|------|------|
| 1. 封面 | ~50 字 | <1% |
| 2. 开场白 | ~100 字 | <1% |
| 3. 前提说明 | ~300-500 字 | 2-3% |
| 4. 基本情况 | ~1500-3000 字 | 10-15% |
| **5. 重点问题** | **~10000-20000 字** | **50-65%（核心）** |
| 6. 投资方案 | ~1000-2000 字 | 5-10% |
| 7. 风险总结 | ~500-1000 字 | 3-5% |
| 8. 落款 | ~50 字 | <1% |
| **合计** | **~15000-27000 字** | 15-35 页 Word |

> **二轮/追加报告**：约首轮 1/2~等长，增加"前次风险追踪表"。详见 writing_patterns.md §5。

### Ch.1-3 前言与前提

封面：公司全称 + 报告标题（"重大事项及核心法律问题风控报告"）+ 版本号 + 日期（可选密级、项目编号）。

开场白（~100 字，一段）：
```
各位投委会委员：
根据公司安排，风险控制部就{公司全称}（以下简称"{简称}"、"公司"或"目标公司"）投资项目所涉及的重大事项及核心法律问题，出具本报告如下，供各位委员投资决策时参考。
```

前提说明的标准素材清单（7 项）：投资建议书✅ / 法律尽调报告（律所+时间）✅ / 财务尽调报告（会所+时间）❌ / 公司基础材料✅ / 管理层访谈纪要（dd-interview）✅ / 行业与 IPO 研究（dd-prep）✅ / 尽调核查表（dd-check）✅。

资料缺失时（V0.xd 版本）在前提说明中列出缺失声明（逐项标注 ✅已有 / ❌待补 及原因），并声明：正文中以 `【待补·Pxxx】` 标注受缺失资料影响的分析段落，资料到位后逐项更新消除标注。

### Ch.4 基本情况

| 子节 | 内容 | 数据来源 | 必含 |
|------|------|---------|------|
| 4.1 股权架构 | 股权穿透（文字层级描述）、控股股东、实控人、员工持股平台 | 工商缓存 + 公司章程 | ✅ |
| 4.2 创始团队 | 创始人背景、持股、任职、竞业限制状态、关联企业 | dd-interview + 工商画像 | ✅ |
| 4.3 历史沿革 | 设立→增资→股改变更，重大事件、历史瑕疵 | 工商变更记录 + dd-check | ✅ |
| 4.4 行业监管政策 | 行业准入、资质要求、最新监管动态 | dd-prep 行业研究 | 按需 |
| 4.5 员工持股计划 | ESOP 架构、期权池、已归属/未归属、持有人任职 | dd-interview + 公司材料 | 有 ESOP 时必含 |

撰写要点：超 10 次变更的用表格呈现并标注瑕疵；行业监管政策仅在有特殊准入时单列。

### Ch.5 重点问题（核心章节）

按已确认的分析框架逐条分析。标准报告 4-7 个重点主题，每个主题下含 1-3 个具体风险点。

**每个风险点四段式论述（IRAC 变体，强制遵循）：**

```
【风险点标题】

1、背景/事实情况（I - Issue）
   → 客观描述，引用尽调材料或访谈内容
   → 数据精确：金额、比例、时间、文件号
   → 数据来源标注："根据XX报告""据管理层访谈了解""根据公开信息"

2、监管规则/法律依据（R - Rule）
   → 引用法规/指引/案例（注明出处）
   → 上位法（《公司法》《证券法》、交易所审核问答）
   → 监管规则（交易所指引、窗口指导、典型案例）与行业惯例

3、风险分析/论证（A - Analysis）
   → 结合具体情况分析；同业对比（同行业上市/在审企业）
   → 定量分析：占比、倍数、阈值对比
   → 说明解释空间（如有）
   → 辩证视角：既提示风险，也承认缓释措施的有效性

风控提示：（C - Conclusion）
   → 明确的风险判断 + 具体建议
   → 语气严格匹配风险等级（见 §8 / references 语气模板）
   → 直接衔接交易文件："建议在交易文件中约定…"
```

**法条/监管规则时效复核**（执行 AC3 前必做）：报告中引用的每条法条与监管规则，须核验其是否为现行有效版本（法规修订频繁，如《反不正当竞争法》2025 修订后条文序号已变）；核验经 legal-research（CONTRACT §7.5，含手工核验降级）执行并产出 authority_record，未核验的条号引用降级为"依据某某法相关规定"表述并记录待核。

**高频分析框架（6 个，writing_patterns.md §2）：**

| 框架 | 适用场景 | 核心结构 |
|------|---------|---------|
| 四维度矩阵式 | 关联交易/独立性 | 研发×采购×资金×人员 × 历史/现存/未来 |
| 三段式论证 | 无实控人/控制权 | 现状→法律分析→后续计划+时间线 |
| 定量→定性→建议 | 税务/财务风险 | 补税金额→税率差影响→风控提示 |
| 逐条摘录→评价 | 保障条款 | 条款原文→逐条分析→保障力度评价 |
| 趋势→阈值→预判 | 关联交易趋势 | 当前占比+业绩承诺→可能突破审核线 |
| 双向论证+差异点 | 关联方认定争议 | 正方理由+反方理由+差异点 |

**5.X 其他关注事项（中低风险表格化处理）：** 中低🔵/低🟢 不展开四段式，统一放表格（关注事项 | 情况说明 | 风险等级）；**中🟡及以上必须在正文展开**。

准入门槛（5 项，实际通常 3-5 项、不超过 5 项）：
1. **等级门槛**：必须 ≤ 中低🔵
2. **去重门槛**：不得与正文重复
3. **实质价值门槛**：正常商业安排、普遍不构成障碍、已在其他章节覆盖的不纳入
4. **财务数据法律视角**：关注商誉减值/在建工程转固等异常**背后的底层法律风险**（收购标的变脸/合同误导/对赌异常），非会计处理本身
5. **精简原则**：超过 5 项说明过滤不足

**信息保真规则**：每个事实性陈述标注 Dossier 来源；风险编号一旦分配跨版本不变（CONTRACT §5）；新增追加编号；合并保留较早编号并注明合并关系。

### Ch.6 投资方案评估

| 子节 | 内容 | 必含 |
|------|------|------|
| 6.1 投资方案概述 | 投资方式、估值、融资额、投资后持股比例 | ✅ |
| 6.2 回购/对赌安排 | 回购触发条件、对赌指标、利率、偿付能力 | ✅ |
| 6.3 股东权利评价 | 信息权、知情权、清算优先权、反稀释等 | ✅ |
| 6.4 前轮投资人权利 | 已有特殊权利梳理 | 有前轮时必含 |
| 6.5 风控建议 | 需补充的保护条款、交割前提、陈保要求 | ✅ |

评价逻辑：完备性检查（回购/对赌/信息权/知情权/清算优先权/反稀释是否齐全）→ 触发条件检查（是否合理、是否与上市冲突）→ 兜底责任检查（创始股东对交割前事项的赔偿责任是否覆盖）→ 前轮权利保全（是否只增不减）。资料不全时只写有书面依据的子节，无依据子节标注【待补·Pxxx】并列入 pending_materials。

**老股受让项目在 6.1 前加专项三问：** ①卖方动因——大股东退出接盘型转让＝资金不进公司，须核查转让原因与转让款去向；②领售权归属——受让股权是否仍受领售权支配、领售估值门槛与受让估值的落差；③回购权承继——卖方是否为回购义务人、受让股权对应的回购金额口径（是否含溢价）。

### Ch.7 风险总结

**7.1 风险矩阵汇总表（必含）**：大类 | 风险点 | 等级（🔴🟠🟡🔵🟢）| 缓释措施 | 报告位置 | clause_mapping。同步产出 `risk_matrix.json`，每项含 `clause_mapping_hints`（见 §9）；涉及法律义务、监管要求或上市规则的风险项，通过 `legal_propositions` 字段引用 legal-research 产出的 authority_record（proposition_id，CONTRACT §7.5），纯交易执行/事实核查/商业依赖类风险不设置此字段。字段形态：

```json
{
  "risk_id": "R03",
  "legal_propositions": ["L003", "L011"],
  ...
}
```

**7.2 总体风控结论**：通过（无高风险项或已解决）/ 有条件通过（存在中高/中风险项，可整改/承诺/条款缓释）/ 不建议（存在无法缓释的高风险项）。分布→结论映射见 references §2.3。

**结论归因表述（"有条件通过"禁止掩盖归因）：** 对"中风险集中但无否决级风险"的项目，结论须二选一明示：①风险可解释但**无收敛路径**——风险均有依据和解释，但缺乏可执行的整改/收敛方案；②**节奏不匹配**——尽调-上会周期与项目融资节奏错配。两者均须列明缺失的收敛条件。交易结构本身无财务投资人位置（如增资改道产权交易所挂牌）的，直接说明**结构性路径排斥**。报告定位是风险揭示而非投资决策：风险识别成立的错失型结局，责任不在风控报告。

### Ch.8 落款

部门（风险控制部）+ 撰稿人 + 复核人 + 日期。文末注明"本报告仅供内部投资决策参考，请勿外传"。

## 8. 风险等级体系（速查）

> **完整规则见 [references/risk_classification_and_rating.md](./references/risk_classification_and_rating.md)**：五级分类判定标准与典型示例、五档语气模板、五大评级核心原则（现实vs潜在、上市影响、常见瑕疵降级、行业特异性例外、趋势校准）、可缓释性判断、结论映射、投资机构五大核心关切与决策深层逻辑。**读取时机**：撰写 Ch.5 / Ch.7、评定风险等级时。

- 潜在风险评级上限 = 中🟡；非审核红线事项 ≠ 高🔴/中高🟠
- 未上市企业常见合规瑕疵 → 中低🔵/低🟢；已整改完毕 → 降级处理
- 语气模板与等级严格绑定（"风控提示"措辞逐级不同），不得混用

## 9. clause_mapping_hints（下游 txn-docs 的唯一桥接）

`risk_matrix.json` 每项风险必须含 `clause_mapping_hints` 字段，经**条款分类决策树**判断（完整决策树、字段结构、示例见 [references/writing_techniques.md](./references/writing_techniques.md) §5.4）：

1. 确认现状为真 → 陈述保证（增资协议-附件二）
2. 交割前必须完成 → 先决条件（增资协议-附件一/第三条）
3. 交割后未来要做 → 交割后承诺（增资协议-第五条）
4. 投资人权利保障 → 特殊权利（股东协议-第七条）
5. 公司治理安排 → 治理条款（股东协议-第三/四/五条）

一项风险可映射多个类型，`primary_type` 标注所有适用类型。映射规则方法论保留于 `templates/clause_mapping_rules.json`。

## 10. 迭代、转写与下游衔接（速查）

> **完整规则见 [references/iteration_and_handoff.md](./references/iteration_and_handoff.md)**。**读取时机**：迭代修订读八-A；转写投委会版读八-B；报告完成后读八-B.5（Dossier 回填）和八-C（下游衔接）。

- **V0.xd 迭代闭环**：V0.1d 初稿（三重标注：前言声明+内联【待补·Pxxx】+JSON）→ 补充资料→增量核查→V0.xd 逐轮迭代 → V1.0d 定稿（清标注、pending 清零）
- **pending_materials 闭环**：缺失资料逐项登记（影响章节+confidence 影响），补充后逐项 resolved，与正文标注一一对应
- **confidence 标注**：高（有书面材料）/ 中（访谈确认）/ 待确认（仅一方陈述或推断）；仅基于访谈的风险点在 risk_matrix 中标注
- **批量更新自动校准**：批量更新后输出 4 项校准清单（等级变动+理由/数据源一致性/新增去重/其他关注事项准入），把"用户事后逐条修正"前置为"AI 主动校准+一次性确认"
- **投委会版转写**：从底稿原版重新转写（不在前次投委会版上修改）；5 段式分段转写；"消除重复"≠"省略内容"，同一事实一次到位（两段式融合叙事）；按 writing_patterns.md §10.5 完成自检

## 13. 异常与边界处理

| 场景 | 处理 |
|------|------|
| Dossier 信息不足（关键章节多为 `[推断]`/`📌待核实`） | 暂停初稿，回 Phase 2 补充核查 |
| 风险编号漂移 | 一致性检查（AC4）发现并修正；编号一旦分配跨版本不变 |
| 扫描件未 OCR / OCR 不可用 | 按 AC5 显式标注"本项未核查，原因：…"，列入 pending_materials |
| 知识库主题/行业模块缺失（开源基线待恢复） | 用通用框架论述，标注 `[通用框架，待补充行业知识]` |
| IRAC 不闭合 / 跨章事实矛盾 | 交付前一致性检查发现，回补缺失环节；以 Dossier 字段级溯源为准修正 |
| dd-check 核查表缺失 | 风险识别依赖访谈关注要点+行业研究+工商数据；仅基于访谈的风险点标注 `confidence: 待确认/中` |

## 14. 数据衔接与数据源优先级

**衔接协议**：投资建议书/外部尽调报告/公司原始资料/前轮报告 ←用户路径；访谈关注要点（四维度归纳）←dd-interview 模块 B；核查结论←dd-check `verification_table.json`；行业与 IPO 研究←`research_*.md`；工商/风险/知产/董监高画像←`qcc_cache.json`。

> **重要**：dd-interview 模块 B 输出的是"多场次关注要点归纳"（四维度），**不含 17 大类映射和风险等级**——分类、定性和分级由本技能完成。

# 写作技巧与条款映射

> 本文件包含报告写作规范和 clause_mapping_hints 规则，撰写 Ch.5 重点问题和生成 risk_matrix.json 时必须读取。

## 五、写作技巧

### 5.1 IRAC 变体（四段式组织参考）

四段式是展开重大事项的组织参考（SKILL.md §7 Ch.5 分析主线的呈现形式之一），不为凑结构添加内容：

1、背景/事实情况——客观描述，引用尽调材料或访谈内容；数据精确（金额、比例、时间、文件号）；数据来源标注（"根据XX报告""据管理层访谈了解""根据公开信息"）
2、监管规则/法律依据——引用法规/指引/案例并注明出处（经 legal-research 时效核验）；上位法与监管规则（交易所指引、审核问答、典型案例）、行业惯例
3、风险分析/论证——结合具体情况分析；同业对比；定量分析（占比、倍数、阈值）；说明解释空间；辩证视角，既提示风险也承认缓释措施的有效性
风控提示——明确的风险判断 + 具体建议；语气严格匹配风险等级（见 risk_classification_and_rating 语气模板）；直接衔接交易文件（"建议在交易文件中约定…"）

### 5.2 措辞原则

| 原则 | ✅ 正确 | ❌ 错误 |
|------|--------|--------|
| 客观中立 | "存在...风险"、"建议..." | "这个风险太大了" |
| 有据可依 | "根据《广告法》第X条..." | "法律上可能有问题" |
| 留有余地 | "原则上...但存在不确定性" | "肯定..." |
| 明确建议 | "建议在交易文件中要求..." | "需要注意一下" |

### 5.3 引用规范

| 引用对象 | 格式 |
|---------|------|
| 法律法规 | 《名称》第X条 |
| 监管指引 | 《监管规则适用指引——发行类第X号》 |
| 案例 | 参考案例：{公司名}{事件}，{时间} |
| 访谈 | "根据访谈了解"、"据管理层称" |
| 公开信息 | "根据公开信息显示"、"根据媒体报道" |
| 中介机构 | "根据{律所}出具的法律尽调报告" |

### 5.4 clause_mapping_hints 规则

每项风险在输出 risk_matrix.json 时，必须增加 `clause_mapping_hints` 字段，经过"条款分类决策树"判断：

1. 确认现状为真 → type="陈述保证"，归属增资协议-附件二
2. 交割前必须完成 → type="先决条件"，归属增资协议-附件一/第三条
3. 交割后未来要做 → type="交割后承诺"，归属增资协议-第五条
4. 投资人权利保障 → type="特殊权利"，归属股东协议-第七条
5. 公司治理安排 → type="治理条款"，归属股东协议-第三/四/五条

**重要：** 一项风险可映射多个类型（如"IDC牌照续期中"同时需陈述保证+交割后承诺），primary_type 标注所有适用类型。

**映射执行要点（决策树直接执行，不走脚本）：**
1. 混合类型必须拆分（如"牌照正在续期"= 陈述保证【确认现状】+ 交割后承诺【限期完成续期】）
2. `suggested_clauses` 的具体条款措辞由撰写者基于项目情况拟定——决策树只给类型和方向
3. 无法映射的风险发现不得静默丢弃：在 `rationale` 中说明并交由 txn-docs 环节人工判断
4. 配套规则表（关键词→条款类型）保留于 `templates/clause_mapping_rules.json`，可作决策树结论的交叉校验参考

**字段结构：**
```json
{
  "risk_id": "R03",
  "risk_description": "IDC牌照续期中，存在业务合规风险",
  "risk_level": "中高🟠",
  "clause_mapping_hints": {
    "primary_type": "陈述保证+交割后承诺",
    "rationale": "现状（正在续期）+未来承诺（限期完成续期）",
    "suggested_clauses": [
      {
        "type": "陈述保证",
        "content": "公司陈述并保证，截至交割日，公司正在按照适用法律申请IDC牌照续期",
        "target_file": "增资协议-附件二"
      },
      {
        "type": "交割后承诺",
        "content": "公司承诺交割后6个月内完成IDC牌照续期，逾期未完成则创始人承担兜底责任",
        "target_file": "增资协议-第五条"
      }
    ]
  }
}
```

### 5.6 常见事项的正向分析方法

对出过错的事项，沉淀的是完整分析方法，不是禁令。以下四类是高频场景的分析路径；通用底线（来源可回溯、单方陈述不充作已确认事实、未决冲突如实呈现）由 CONTRACT §2 与 SKILL.md 写作底线统一约束，此处不重复。

**实缴与承诺履行**：分别整理公示记录、出资凭证、承诺内容与履行期限，比较各项证据各自支持的事实，再判断履行状态（已履行 / 部分履行 / 无法确认）及其对出资充实性与交易的影响。公示渠道未见实缴登记只是该渠道的结果，实际缴纳以入资凭证等原始证据认定；承诺是否违反，比较承诺文本与履行事实后得出。

**投资条款缺失**：列明已取得的交易安排，识别尚待评估的投资人权利（回购、清算优先、反稀释、信息权等），提出所需文件及其对交易判断的作用。表述示例：现有材料未包含投资协议及股东协议，尚无法评估回购、清算优先和反稀释等安排对本次投资的保障程度；取得相关协议或条款清单后，应结合义务主体、触发条件及履行能力逐项评估。

**风险尚未发生（潜在风险）**：描述风险事件与触发条件，列出支持其发生可能性的证据及证据缺口，评估潜在影响与已有缓释的有效性，据此形成评级或暂缓判断（评估路径见 [risk_classification_and_rating.md](./risk_classification_and_rating.md) 原则一）。

**期限相关判断（竞业、诉讼时效、出资期限等）**：建立义务发生、履行、到期与争议处理的时间线，分别分析当前义务与历史责任；期限届满只是时间线上的一个事件，是否仍有现实责任取决于履行情况、既往违约与追诉事实。

**判断质量的写法对照**："核心技术权属存在风险，建议进一步核查"不合格，没说事实从哪来、缺什么、查什么；"公司称核心技术为自主研发，但现有材料尚未说明创始人前任职期间形成的相关成果如何与现有技术区分；目前不足以确认权属清晰，也不足以认定侵权；建议取得前任职协议、研发时间线及成果归属文件后再判断是否设置交割条件"合格，事实分层、依据、分寸、动作齐备。

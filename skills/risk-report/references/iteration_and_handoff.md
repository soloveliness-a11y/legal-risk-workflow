# 报告迭代流程、投委会版转写与下游衔接

> 本文件包含报告迭代流程（八-A）、投委会版转写（八-B）、回填Dossier（八-B.5）、下游衔接（八-C）。
> 按需读取：迭代修订时读八-A，转写投委会版时读八-B，完成报告后读八-B.5 和八-C。

## 八-A、报告迭代流程

> 所有报告都遵循 V0.1d → V0.xd → V1.0d 的迭代路径。资料不全时先行出V0.1d，通过补充资料逐步迭代至定稿。

### 三阶段闭环

```
阶段一：初稿（V0.1d）
  → 基于访谈+行业研究+QCC撰写完整报告
  → 输出：初稿报告 + pending_materials.json + risk_matrix（含confidence）
  → 正文：三重标注（前言声明+内联【待补·Pxxx】+JSON）

        ↓ 补充资料到达（可N轮迭代）

阶段二：迭代（V0.2d → V0.3d → ...）
  → 补充资料 → dd-check T3增量核查 → risk-report迭代更新
  → 更新：pending_materials（逐项消除）+ risk_matrix（confidence升级）
  → 每轮迭代后做轻量自检

        ↓ 终止条件满足

阶段三：定稿（V1.0d）
  → 清除所有【待补·Pxxx】标注
  → pending_materials 全部 resolved
  → 进入正式 report-review 流程
```

### 版本标注体系

> 版本号体系遵循 CONTRACT §8：`V0.xd` 草稿迭代 → `V1.0d` 定稿 → `V1.xd` 封版后修订。

| 版本 | 含义 | 触发条件 |
|------|------|---------|
| V0.1d | 首版初稿 | 首次撰写 |
| V0.2d, V0.3d... | 迭代版 | 每轮补充资料递增 |
| V1.0d | 资料齐备完整版（定稿） | pending清零或用户确认 |
| V1.1d | review后修订版（封版后修订） | report-review反馈后 |
| V2.0d | 大预审后终稿 | 大预审通过 |

**命名规则：** 文件名：`{公司名}-法律风控报告-V0.1d-{日期}.docx`。每次迭代保留历史版本。

### pending_materials.json 结构

```json
{
  "draft_version": "V0.1d",
  "project_name": "",
  "last_updated": "",
  "pending_items": [
    {
      "id": "P001",
      "material": "公司章程及历次修订",
      "source": "dd-check清单第2.1项",
      "affects_chapters": ["5.2 股权架构", "5.3 历史沿革"],
      "confidence_impact": "中",
      "status": "pending",
      "resolved_in_version": null,
      "notes": ""
    }
  ],
  "statistics": { "total": 0, "pending": 0, "resolved": 0 }
}
```

**迭代更新：** 匹配 pending item → status 改 `"resolved"` → 新发现的缺失资料新增 item → 更新 statistics。

### risk_matrix confidence 字段

| confidence | 含义 | 触发条件 |
|------------|------|---------|
| **高** | 有书面材料支撑 | 合同/证照/官方文件已阅 |
| **中** | 访谈确认但无书面材料 | 访谈中被访谈人确认 |
| **待确认** | 仅有一方陈述或推断 | 仅有QCC数据或行业研究推断 |

```json
{
  "risk_id": "R003",
  "level": "中高",
  "confidence": "待确认",
  "confidence_reason": "关联交易金额基于访谈陈述，待审计报告验证"
}
```

**V1.0d 定稿时：** 所有 confidence 应升级为"高"，或用户确认接受当前等级。

### 章节撰写策略

| 章节 | 策略 | 说明 |
|------|------|------|
| 封面+开场白 | ✅正常写 | — |
| 报告出具前提 | ✅特殊处理 | 列出资料缺失声明 |
| 基本情况 | ✅正常写 | QCC+访谈足够支撑 |
| 重点问题分析 | ✅正常写 | 核心章节，受影响段落加【待补·Pxxx】 |
| 投资方案评价 | ⚠️简化或暂缓 | 需交易文件/外部报告支撑，资料不全时仅写能确认的部分 |
| 风险总结/矩阵 | ✅正常写 | 含confidence字段 |

### 迭代终止条件（满足任一）

1. 所有 `confidence=待确认` 的风险点已获书面验证
2. 用户确认"剩余待补资料不影响核心风险判断"
3. dd-check 至少 T2 已完成

### 迭代轻量自检（每轮V0.xd更新后）

| 自检项 | 标准 |
|--------|------|
| 资料覆盖度 | 已解决的pending item对应章节已更新 |
| 风险等级漂移 | 新资料导致的等级变化是否合理 |
| 一致性 | 同一事实在报告不同位置表述是否一致 |

### 批量更新后自动校准

> **触发**：risk-report执行批量更新时，输出结果前**自动执行**校准清单。

| 校准项 | 输出格式 |
|--------|---------|
| 风险等级变动清单 | 表格：风险ID \| 旧等级 \| 新等级 \| 变动理由 \| 趋势校准 |
| 数据源一致性 | 逐项列出问题（如有） |
| 新增内容去重 | 标注重复位置（如有） |
| 其他关注事项准入 | 排除理由（如有） |

> **核心目的**：将"用户事后逐条修正"前置为"AI主动校准+用户一次性确认"。

## 八-B、投委会版转写流程

> **触发**：用户说"撰写投委会版"/"转写投委会版"
> **前提**：底稿版（V0.xd 或 V1.0d）已存在且内容稳定

### 转写前确认

1. 确认底稿版文件路径
2. 确认投资方案概要是否已可写入
3. **强制**：读取 `writing_patterns.md §10.5` 逐章转写守则

### 核心原则

- **从底稿原版重新转写，不在前次投委会版上修改**
- **"消除重复"≠"省略内容"**：融合叙事的核心是同一事实只说一次、一次到位

### 转写执行（分段输出）

```
第一段：封面 + 致投委会 + 报告前提 + 基本情况（保持底稿原样）
第二段：重点问题 3.1-3.3（两段式融合叙事）
第三段：重点问题 3.4-3.7（两段式融合叙事）
第四段：投资人保护条款（4方向：先决条件/交割后承诺/陈述保证/赔偿条款）
        + 风险矩阵（简化列）+ 风险总结（含正面因素）+ 投资建议
第五段：落款 + 版本说明
```

每段输出后：追加到投委会版 md 文件 → 确认无截断 → 执行 writing_patterns.md §10.5-C 适用检查项

### 全文自检

全部段落完成后，按 `writing_patterns.md §10.5-C` 完整执行8项自检清单（Q1-Q8）。

### 输出文件

- 文件名：`{公司名}_法律风控报告_投委会版_{版本号}.md`
- 版本号与底稿版一致
- 文末版本说明：注明投委会版与底稿版的差异仅在表述精炼度

## 八-B.5、报告完成后回填项目全景档案

> **定位**：报告撰写完成是 dossier §12 的**最终定稿时机**。

**回填步骤：**

1. 读取当前 dossier → 确认 §12 现有内容
2. 用 risk_matrix.json **覆盖 §12**（按风险等级排序，每项含描述+等级+clause_mapping摘要+总体结论）
3. 更新 §13 信息完备度矩阵
4. 更新 §14 待办事项（与 pending_materials.json 一致）
5. 更新 §0 元信息（last_updated, dossier_version）
6. 更新 §15 来源索引（新增"风控报告 Vx.x"条目）

**质量检查：**
- [ ] §12 与 risk_matrix.json 完全一致
- [ ] §12 包含总体结论
- [ ] §13 信息完备度已更新
- [ ] §14 与 pending_materials.json 一致
- [ ] §0 元信息已更新

## 八-C、与下游 Skill 的衔接

**输出 → report-review：**

```json
{
  "risk-report_draft": "{报告全文/文件路径}",
  "risk_matrix": "{风险矩阵 - 含clause_mapping_hints}",
  "risk_statistics": "五级风险等级数量统计",
  "conclusion": "通过/有条件通过/不建议",
  "risk_identification_notes": "{风险识别过程中的关键判断和依据}"
}
```

**risk_matrix.json 每项风险必须包含 `clause_mapping_hints`**（见 writing_techniques.md §5.4），用于向 txn-docs 提供条款映射建议。

**迭代版额外字段：** `confidence` + `confidence_reason`。V1.0d 后 confidence 应全部为"高"。

**条件分支（复核后）：**

```
if report-review.结论 == "不通过" or 存在无法缓释的高风险:
    return "项目终止或暂缓"
elif report-review.结论 == "有条件通过":
    继续 → 落实条件 → txn-docs
else:
    直接 → txn-docs
```

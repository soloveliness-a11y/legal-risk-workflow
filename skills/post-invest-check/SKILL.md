# post-invest-check — 投后法律支持

> **注：本技能设计未经真实项目完整运行验证。**

> 遵循 [CONTRACT](../risk-workflow/CONTRACT.md)。本文件只描述投后跟踪的专业逻辑；数据总线（§1）、Dossier 更新（§2.4）、output 状态文件（§3）、检查点 CP4 审批语义（§4.1）与子确认（§4.2）、验收契约 AC4（§6）、工商数据源适配器（§7.1）以契约为准。

## 定位

**项目清单的详细法律层。** 项目清单管宏观状态（项目阶段、签约/打款/工商），post-invest-check 管每个项目下面的法律细节（交割后义务、回购/对赌跟踪、数据源变更预警）。在主工作流中位于 txn-docs（CP4）之后，是风控链路的投后终点环节。

```
项目清单（宏观层）              post-invest-check（法律层）
├── 项目阶段: 已完成            ├── 交割后义务: 工商✅ 核心人员协议⏳ 信息披露❌
├── 签约: 已签约                ├── 回购权: 2028年到期，当前未触发
├── 核心风险主题                ├── 对赌: 2026年净利润目标5000万，Q3已达60%
└── 备注                        ├── 数据源变更: 新增诉讼1件(合同纠纷)
                                └── 预警: 核心人员协议签署期限还剩10天
```

## 触发条件

- 项目签约/打款后，首次建立法律台账
- 用户主动询问某项目投后情况
- 定期数据源扫描发现变更
- 触发事件（回购/对赌到期、新增融资、重大诉讼、核心人员变动等）

## 项目清单输入（抽象接口）

**接口语义**：提供"已交割项目清单"的任意来源——Excel 控制表、CSV、Markdown 清单或口述均可。读取字段：项目名称、目标企业名称、项目阶段、签约/打款/工商状态、核心风险主题、备注。

| 筛选条件 | 操作 |
|---------|------|
| 项目阶段="已完成" + 已签约 + 已打款 | 已交割项目 → 建立或更新法律台账 |
| 项目阶段="投委会" + 未签约 | 待签约项目 → 提醒签约进展 |
| 备注含"需要跟进" | 重点关注项目 |

清单来源不可读时，提示用户手动提供项目信息，基于 Dossier、交易文件与**交割确认函**（法定输入：陈保虚假与交割日陈述的关键证据）建台账（CONTRACT AC5 降级显式化）。**首次建台账的主路径即此**：基于 Dossier+交易文件+交割确认函直接构建，项目清单筛选是已有台账后的日常入口而非前置条件。台账须含**投资人自身动作**行（观察员委派、材料索取等我方义务，不只盯公司履约）。

**「AI 不直接改用户主表」原则**：检查完成后输出结构化更新建议（见下），用户确认后**由用户手动更新**清单文件，AI 不直接修改。

**核心风险自动输出规则**：
1. 首次建台账：从条款落实表 + 风险矩阵提取 Top 3-5 核心风险主题
2. 日常检查风险变化时：更新核心风险主题
3. 事件触发时：将触发事件对应的风险加入

提取规则：来源优先级 条款落实表 > 风险矩阵 > 投后检查发现；筛选风险等级≥中，最多 5 条。

```json
"project_list_updates": [
  {
    "项目名称": "某项目",
    "目标企业名称": "某公司",
    "更新字段": "核心风险主题",
    "建议值": "知识产权权属风险(前雇主主张); 创始人竞业限制义务; 境外数据合规",
    "更新来源": "首次建台账 — 条款落实表+风险矩阵提取"
  }
]
```

## 法律台账（核心输出，6 表）

从交易文件中提取关键法律条款并持续跟踪。**risk_id 贯穿全表**——台账中的风险条目与 risk_matrix.json、条款落实表中的 risk_id 必须一致（CONTRACT §5 / AC4）。台账由模型按下方 schema 直接生成与更新，不依赖脚本。

```
项目名称: {公司名}
投资金额: {金额}    持股比例: {比例}    交割日期: {日期}
上市计划: {计划}

一、交割后义务落实
| 序号 | risk_id | 事项 | 协议约定期限 | 当前状态 | 逾期风险 |
|------|---------|------|------------|---------|---------|
| 1 | R02 | 工商变更登记 | 交割后20工作日 | ✅已完成 | - |
| 2 | R02 | 核心人员协议签署 | 交割后90日 | ⏳进行中(还剩10天) | ⚠️即将逾期 |
| 3 | R07 | 首次信息披露报告 | 交割后季度末 | ❌未提交 | 🔴已逾期 |

一-A、陈述保证监控清单（从交易文件提取）
| 序号 | risk_id | 陈述保证条款 | 监控方式 | 监控频率 | 当前状态 |
|------|---------|------------|---------|---------|---------|
| 1 | R01 | "公司股权不存在代持" | 数据源股权变更扫描 | 每季度 | ✅无异常 |
| 2 | R04 | "不存在未披露重大诉讼" | 数据源诉讼扫描 | 每季度 | ⚠️新增1件 |

二、回购条款
| 项目 | 内容 |
|------|------|
| 触发条件 | 未在约定日期前完成上市/实控人变更/重大违约等 |
| 回购期限 | 触发后X日内书面通知 |
| 回购价格 | 投资款×(1+年化8%×N)+已宣告未付股息 |
| 回购义务人 | 公司+创始人连带 |
| 当前状态 | 未触发 / 已触发待行权 / 行权中 / 已完成 |

三、对赌里程碑（如有）
| 时间节点 | 业绩目标 | 当前进展 | 达成状态 |

四、投资人特别权利
| 权利类型 | 核心条款 | 当前状态 |

五、风控条款落实跟踪
| risk_id | 风控发现 | 合同映射条款 | 当前落实状态 |
```

如需 AI 间一致性，可同时产出结构化 JSON（六表对应 `post_closing_obligations` / `representations_warranties_monitoring` / `redemption_clause` / `vod_milestones` / `investor_special_rights` / `risk_clause_tracking` 六个子结构，每条含 risk_id 字段；枚举值：义务状态 completed/in_progress/overdue/not_started，监控状态 normal/abnormal，对赌达成 achieved/on_track/at_risk/missed）。Markdown 台账为必用格式（人类可读），JSON 可选。

## 检查清单

### 首次交割后检查（建台账时）

| # | 检查项 | 检查依据 | 关注点 |
|---|--------|---------|-------|
| 1 | 工商变更登记 | 增资协议约定 | 20-30 工作日内完成 |
| 2 | 章程修订版签署 | 股东协议约定 | 反映新股权结构和治理结构 |
| 3 | 股东名册更新 | 增资协议约定 | 包含本轮投资人 |
| 4 | 出资证明书签发 | 增资协议约定 | 已签发给投资人 |
| 5 | 核心人员协议签署 | 交割后义务 | 劳动+竞业+保密+IP归属，注意期限 |
| 6 | 信息披露首次报告 | 知情权约定 | 按约定时间提交 |
| 7 | 交割后义务全部启动 | due_milestones | 各项义务按时间表启动 |

### 日常检查

| # | 检查项 | 检查方式 |
|---|--------|---------|
| 1 | 信息披露义务履行 | 对照知情权约定，检查财务报告/业务数据是否按时提交 |
| 2 | 交割后义务进展 | 对照 due_milestones，检查各项义务完成状态 |
| 3 | 对赌业绩跟踪 | 对照对赌条款，评估当前业绩达成进度 |
| 4 | 陈述保证违反检查 | 对照陈述保证监控清单，逐项核查是否有违反的新情况 |
| 5 | 数据源变更对比 | 与上次缓存对比，发现变更 |

### 事件触发检查

| 触发事件 | 检查重点 |
|----------|---------|
| 回购条款触发/到期 | 回购条件是否成就、行权期限、回购价格计算、创始人偿付能力 |
| 业绩对赌到期 | 业绩完成情况核实、补偿义务计算、是否需要审计 |
| 新增融资 | 对本轮投资人权益影响（反稀释/优先认购/最惠国） |
| 重大诉讼/行政处罚 | 评估对投资的影响、陈述保证是否违反 |
| 核心人员变动 | 创始人/核心技术人员离职、竞业限制执行 |
| 控制权变更 | 清算优先权是否触发、投资人否决权行使 |
| 行业政策重大变动 | 对公司业务和上市计划的影响评估 |
| 基金临近到期/进入清算期 | 清算启动时限（到期后 3 个月）与在持项目处置分档路径，详见 `knowledge-base/风控发现沉淀/07_国资与清算退出.md` §7.5-7.6 |
| 国资背景主体转让份额/股权 | 先按"转让方主体 × 基金法律形式"矩阵定位程序（32号令链条/评估/进场/试点平台），详见同文件 §7.1-7.4 |

## 定期数据源扫描

遵循 CONTRACT §7.1 工商数据源适配器（自动查询或手工采集，填同一 schema）：

```
1. 通过适配器采集目标企业数据（含高管维度画像），结果存 qcc_cache_{date}.json
2. 读取上一次缓存，对比差异（缓存 >7 天需复查，CONTRACT §7.1）
3. 差异项触发风险预警

企业维度对比重点：新增/解除诉讼、股权变更/出质/冻结、新增行政处罚、
                 注册资本/经营范围变更、新增对外投资、新增/失效知识产权
高管维度对比重点：新增/离职关联企业、新增对外投资、法人/董事变更、
                 新增涉诉/失信/股权出质/冻结
```

高管维度扫描触发：每季度常规扫描同步执行；或核心人员变动事件立即触发。无适配器时提示用户手动提供变更材料（AC5 降级显式化）；已有历史缓存的本地对比不受影响。

## 预警机制

### 单一维度预警（9 类）

| 预警类型 | 触发条件 | 级别 | 建议措施 |
|---------|---------|------|---------|
| 交割后义务逾期 | 约定期限已过仍未完成 | 🔴高 | 书面催促，评估是否构成违约 |
| 回购权即将到期 | 到期前60/30/15日 | 🟠中高 | 提醒决策是否行权 |
| 对赌业绩不达标风险 | 当前业绩<目标60% | 🟠中高 | 跟踪进展，评估补偿方案 |
| 信息披露未按时提交 | 超过约定时间未收到 | 🟡中 | 书面要求提供 |
| 数据源重大变更 | 新增诉讼/股权冻结/行政处罚 | 🔴高 | 评估影响，考虑启动特别检查 |
| 核心人员离职 | 创始人/CTO等离职 | 🔴高 | 评估竞业执行、触发回购可能性 |
| 董监高新增关联企业 | 高管扫描发现新增兼职/投资 | 🟠中高 | 排查同业竞争/利益冲突 |
| 董监高新增涉诉/失信 | 高管扫描发现新增诉讼/失信 | 🔴高 | 评估诚信风险、是否影响经营 |
| 陈述保证违反 | 披露不实/重大遗漏（对照监控清单或数据源变更发现） | 🔴高 | 按协议主张违约金，评估回售权 |

### 复合风险预警升级规则（多维叠加）

单一维度按上表定级；**两个及以上维度同时触发时，按以下规则升级**：

| 叠加场景 | 原级别 | 升级后 | 升级理由 |
|---------|--------|--------|---------|
| 回购权即将到期 + 对赌业绩不达标 | 🟠中高 | 🔴高 | 回购触发概率显著增加，偿付能力存疑 |
| 回购权即将到期 + 新增诉讼/股权冻结 | 🟠中高+🔴高 | 🔴高（紧急） | 创始人偿付能力可能恶化，需立即评估行权 |
| 对赌不达标 + 核心人员离职 | 🟠中高+🔴高 | 🔴高（紧急） | 业绩恢复能力削弱，补偿方案需重新评估 |
| 数据源重大变更 + 信息披露延迟 | 🔴高+🟡中 | 🔴高 | 可能存在未披露的重大负面信息 |
| 交割后义务逾期 + 任何其他预警 | 🔴高+X | 🔴高（紧急） | 已构成违约，叠加其他风险需立即应对 |

**复合预警输出要求**：
1. 列出触发的所有单一维度预警及原级别
2. 说明叠加后的升级逻辑和升级后级别
3. 输出**风险传导分析**："A风险 → 可能触发B条款 → 导致C后果 → 建议D时机行权"
4. 建议**跟踪频率调整**：单一🟠→每月；复合🔴→每周；紧急→立即

### 预警处理（子确认，CONTRACT §4.2）

发现重大预警时暂停并向用户报告详情，提供选项，**用户选择后执行，不自动升级**：

- 选项A：记录预警并调整监控策略（加强跟踪频率、行使信息权）
- 选项B：AI 辅助起草催告函/违约通知（应对逾期/违反陈述保证等）
- 选项C：输出风险应对建议书供投委会/投后管理委员会讨论

台账信息确认后才开始生成投后报告（子确认，记一行日志）。

## 处理流程

```
1. 读取项目清单 → 识别已交割项目，确定检查范围
2. 建立/更新法律台账 → 从交易文件提取关键条款，对照交割后义务逐项检查
3. 数据源扫描（如需） → CONTRACT §7.1 适配器，与历史缓存对比
4. 评估风险变化 → 信息披露、对赌进展、陈述保证等
5. 触发预警 → 逾期/即将到期/重大变更发出预警（单一+复合升级）
6. 生成投后报告（如需） → 按4章模板输出
7. 更新 Dossier → §12/§9/§10/§14
```

投后报告模板（4 章简化版）：

```
封面：{公司名}投后法律跟踪报告（{期间}）
一、项目基本情况 — 项目名称、投资金额、持股比例、交割日期、上市计划
二、协议履行情况 — 交割后义务落实 / 信息披露义务 / 对赌业绩跟踪
三、风险变化与预警 — 数据源变更（与上期对比）/ 行业政策变动 / 预警事项清单
四、结论与建议 — 总体评估 + 下阶段关注重点
```

## 风险升级决策协议

> **核心边界**：post-invest-check 是风控工作流的终点环节（跟踪、监督、预警），不回退到投前状态，不替代决策。

```
可以做:
  ✅ 记录风险、更新台账、调整监控频率
  ✅ 行使信息权，要求公司提供资料/说明
  ✅ 起草催告函、违约通知
  ✅ 评估回购/对赌/违约赔偿条件是否成就
  ✅ 输出风险应对建议书/退出评估报告
  ✅ AI辅助起草回购通知函、股权转让方案

不做:
  ❌ 重新启动尽调流程（投前环节）
  ❌ 起草/修订交易文件（签约环节）
  ❌ 替代投委会/投后管理委员会做投资决策
```

### 4 级决策树（复合升级含**待核实缓冲层**：任一预警处于"待核实"状态时，升级判定挂起至核实完成，避免两个未确认预警机械叠加成紧急级）

```
投后发现新风险
    │
    ├─ 风险评估（3项判断）
    │   ├─ ① 影响范围：仅信息记录 / 影响投后跟踪策略 / 影响投资安全
    │   ├─ ② 紧迫程度：可等待定期检查 / 需尽快处理 / 需立即响应
    │   └─ ③ 是否可依据现有交易文件中的权利进行应对
    │
    └─ 分级决策
        ├─ 🟢 低级（信息记录级）→ 仅更新台账，下次定期跟踪
        │   例：工商信息微调、非核心人员变动
        ├─ 🟡 中级（策略调整级）→ 更新台账+预警+调整跟踪频率+行使信息权
        │   例：关联交易增长较快、信息披露延迟
        ├─ 🟠 中高级（需积极应对）→ AI辅助起草催告函/违约通知+评估回购/对赌/违约条件
        │                        → 输出《风险应对建议书》→ 建议投后管理委员会讨论
        │   例：交割义务严重逾期/核心人员离职/新增重大诉讼/陈述保证违反
        └─ 🔴 高级（重大风险事件）→ 启动退出评估（回购行权/股权转让方案）
                                  → AI辅助起草：回购通知函/股权转让方案/法律程序指引
                                  → 输出《重大风险事件报告》→ 建议提交投委会决策
            例：实控人变更/重大违约/经营状况严重恶化
```

### 风险应对文件模板

**🟠 中高级 — 《风险应对建议书》：**
```
一、风险概述 — 风险事件描述 / 发现时间与来源 / 涉及的交易文件条款
二、影响评估 — 对投资安全的影响 / 对回购对赌的影响 / 对投资人权利的影响
三、应对方案（按优先级） — 方案A：行使信息权 / 方案B：催告函/违约通知 /
                          方案C：启动回购/对赌补偿 / 方案D：建议补充协议谈判
四、建议决策 — 推荐方案及理由 / 时间敏感性 / 需人工确认事项
```

**🔴 高级 — 《重大风险事件报告》：**
```
一、事件概述（事实描述）
二、合同条款对照（触发哪些条款）
三、退出可行性评估 — 回购行权（条件+价格+偿付能力）/ 股权转让（限制+潜在受让方）
四、AI辅助起草文件 — 回购通知函草案 / 股权转让方案草案
五、建议投委会决策事项
```

### 升级终止规则

- 🔴 高级风险直接建议投委会决策，不经过多轮升级
- 单项目连续 2 次中高级 → 自动升级为高级
- 所有升级建议为**人工决策参考**，AI 不自动执行退出/行权
- 升级期间日常检查照常进行（台账标注"升级处理中"）

## 条件分支

| 场景 | 后续动作 |
|------|---------|
| 交割后义务逾期 | → 输出催促函草案 → 评估是否构成违约 |
| 回购权触发 | → 计算回购价格 → 评估偿付能力 → 输出行权建议（是否行权/金额/期限/法律风险提示） |
| 回购权即将到期（60/30/15日） | → 输出到期预警 → 行权vs展期vs放弃利弊对比 → 行权材料清单 |
| 对赌业绩不达标 | → 计算补偿金额/股权 → 评估是否需审计确认 → 输出补偿方案 |
| 新增融资影响权益 | → 反稀释调整 → 优先认购权评估 → 最惠国适用 → 权益影响评估报告 |
| 数据源重大变更 | → 变更影响评估 → 是否启动特别检查 → 是否触发陈述保证违反 |
| 无重大事项 | → 更新台账状态 → 下次定期检查 |
| 退出触发条件 | → 回购行权：回购通知函草案+法律程序指引 / 股权转让：转让限制分析（优先购买权/共同出售权/锁定期）+起草转让方案 / 上市退出：锁定期合规+退出时间表+减持规则适用分析 |

## Dossier 更新

post-invest-check 是 Dossier 的**投后更新入口**（遵循 CONTRACT §2.4）：

1. **§12 风险信号**：已缓解→标注"✅已缓解"；新增→追加；等级变化→更新
2. **§9 合规与监管**：数据源扫描发现的变更
3. **§10 诉讼与争议**：新增诉讼/仲裁/执行信息
4. **§14 待办事项**：交割后义务完成/逾期状态同步
5. **§0 / §15**：元信息与来源索引同步

质量要求：§12 已反映投后发现；§9-§10 已更新扫描结果；§14 义务状态已同步；投后变更与历史信息矛盾时按 CONTRACT §2.4 标注 ⚠️ 并登记待核实。

## 方法论沉淀

投后检查中发现的经验（新风险类型、行业特有风险、缓释措施效果），默认写入**仓库外的私有知识库**；公共知识库（风控发现沉淀/行业专项检查库）仅接受去除个案信息的通用方法，经独立发布审核后更新。示例维度：

- 项目维度：高校教授兼职持股在投后是否引发合规问题
- 行业维度：医疗器械注册证到期续展对经营的影响
- 缓释措施：代持确认函+质押方案的实际执行效果

## 输出

output.json 按 CONTRACT §3 最小 schema，可按需追加扩展字段 `check_focus`（首次建台账/日常检查/事件触发/定期扫描）。

产出文件（`07_post_invest/`）：法律台账（md 先行，docx 可选）、风险预警记录、risk_response_request.json（升级时）、投后报告（如需）。

## 异常与边界处理

| 场景 | 触发条件 | 处理动作 |
|------|---------|---------|
| 交割后义务逾期 | 协议约定的完成期限已过，公司未履行 | 生成 `⚠️逾期预警`，标注逾期天数+法律后果 |
| 预警触发无法判断 | 边界条件模糊（如"重大不利变化"定义不清） | 保守触发预警，标注 `📌需人工判断严重程度` |
| 定期扫描数据无变化 | 全量复查无 diff | 记录"无变化"，不生成预警 |
| 数据源不可用 | 适配器不可用且无人工材料 | 按 AC5 降级显式化，标注"本项未核查，原因：…" |

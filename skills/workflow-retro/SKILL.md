# 工作流复盘优化器 (Workflow Retro)

> 定位：工作流的元改进机制——不改业务产出，只改"产出是怎么被生产出来的"。审视其他 Skill 的执行过程，把反复出现的偏差沉淀为规则变更，让工作流随实战自我进化。

## 一、触发方式

| 场景 | 条件 | 复盘范围 |
|------|------|---------|
| 步骤完成 | 工作流任一步骤标记完成 | 该步骤及上下游衔接 |
| 阶段完成 | 一个阶段全部步骤 + 检查点通过 | 该阶段完整复盘 |
| 收工复盘 | 当日有工作流活动 | 当日全部活动 |
| 异常复盘 | 执行中出现中断 / 降级 / 返工 | 异常链全路径 |

前置读取（读不完不开始分析）：

1. 对应工作流的 SKILL.md 当前版本（评判基准）
2. 项目执行日志与产出文件（实际发生了什么）
3. 该工作流的 CHANGELOG（区分已知问题与新问题）

本技能不依赖任何宿主私有环境，能读到上述文件即可执行。

## 二、五维度偏差诊断

> 每次复盘逐项分析，每个维度标注：✅ 正常 / ⚠️ 轻微偏差 / 🔴 显著偏差。

### 维度 1：闭环性——问题是否被接住

- 问什么：执行中发现的问题，后来被解决了吗？还是只是被记了下来？
- 看什么：日志中"发现问题"的条目，后续是否有对应修正动作；检查点发现问题后是否真的回到修正步骤，还是带着问题继续走。
- 怎么判：问题有记录、无后续动作 → 🔴；修正了但未回写日志 → ⚠️；发现→修正→验证三环齐全 → ✅。

### 维度 2：熵增——规则是否越积越重

- 问什么：工作流比上个版本更臃肿了吗？新增的规则带来了对应的可靠性提升吗？
- 看什么：SKILL 版本间的行数变化与新增条款；新增规则在本次执行中是否被实际用到；同一约束是否在多处重复定义或口径漂移。
- 怎么判：新增规则从未被触发 → 🔴（纯熵增）；重复定义或口径不一致 → ⚠️；每条新规则有执行证据 → ✅。

### 维度 3：约束有效性——写了的规则有没有被执行

- 问什么：SKILL 里的硬性要求（标签纪律、来源标注、必填字段等），执行时真的做到了吗？
- 看什么：抽 2-3 条硬性约束，对照实际产出逐条核对；约束只写在文档里、无任何校验手段的，标注为"软约束"。
- 怎么判：硬性约束被跳过且无人察觉 → 🔴；靠提醒而非机制保证 → ⚠️；约束有校验兜底 → ✅。

### 维度 4：决策留痕——关键判断能否追溯

- 问什么：事后回看，当时的分支决策（走哪条路、为什么走）能还原吗？
- 看什么：日志中分支点处是否记录了决策依据（读了哪些信息、排除了什么）；同一问题反复回退 / 返工的次数。
- 怎么判：关键决策无记录、无法追溯 → 🔴；有结论但缺依据 → ⚠️；决策 + 依据 + 结果三要素齐全 → ✅。

### 维度 5：恢复能力——失败后怎么回来

- 问什么：出问题之后，工作流是卡死、盲目重试，还是有序恢复？
- 看什么：失败后的重试是否换过思路，还是原样重打；是否走了预定义的降级路径；需要人介入的异常是否及时上报而非静默失败；同类错误是否在同一项目重复出现。
- 怎么判：卡死或静默失败 → 🔴；重试不换思路 / 同类错误重复出现 → ⚠️；按降级路径恢复并留痕 → ✅。

## 三、触发阈值（防复盘噪音）

复盘报告每次都产出，但**修改 SKILL 有硬门槛**：

- 🔴 ≥ 1，或 ⚠️ ≥ 3 → 进入优化提交流程
- 未达阈值 → 只记入"下次复盘关注点"，不改 SKILL

> 设计意图：单次复盘的发现可能是个案噪音，达不到阈值不动流程。连续两次复盘命中同一维度时，该维度可按 ⚠️ ≥ 2 提前提交。

## 四、复盘报告模板

输出 `workflow_retro_YYYY-MM-DD.md`：

```markdown
# 工作流复盘报告 — {日期}

## 一、复盘范围
- 涉及工作流：[Skill 名称 + 版本]
- 涉及项目：[项目名]（如有）
- 执行步骤：[本次复盘覆盖的步骤]
- 触发方式：[步骤完成 / 阶段完成 / 收工复盘 / 异常复盘]

## 二、五维度诊断总览
| 维度 | 状态 | 关键发现 |
|------|------|---------|
| 闭环性 | ✅/⚠️/🔴 | — |
| 熵增 | ✅/⚠️/🔴 | — |
| 约束有效性 | ✅/⚠️/🔴 | — |
| 决策留痕 | ✅/⚠️/🔴 | — |
| 恢复能力 | ✅/⚠️/🔴 | — |

## 三、详细诊断
[每个非 ✅ 维度：偏差描述 + 影响评估 + 修复建议]

## 四、阈值判定
- 🔴 计数：N；⚠️ 计数：N
- 是否达到修改门槛：[是/否]

## 五、优化建议（仅达阈值时填写）
| 优化点 | 当前状态 | 建议变更 | 预期收益 | 风险 |
|--------|---------|---------|---------|------|

## 六、执行记录
- 是否修改 SKILL：[是/否 + 版本变化]
- 下次复盘关注点：[需持续跟踪的问题]
```

## 五、优化提交流程（达阈值后）

1. 输出完整复盘报告。
2. 汇总优化建议，每条注明具体修改位置（改哪个文件、哪一段、改成什么）。
3. 提交审批人决策：
   - 执行 → 更新对应 SKILL.md + version 递增 + 追加 CHANGELOG
   - 暂缓 → 记录为"下次复盘关注点"
   - 拒绝 → 标注原因
4. 涉及工作流结构调整（步骤增减、阶段重组）的变更，必须审批人确认，不自动执行。

## 六、挂接说明

本技能可挂接到主工作流检查点之后触发（检查点通过 → 提示"可执行复盘"）；当前为手动 / 建议触发，未做强制集成。

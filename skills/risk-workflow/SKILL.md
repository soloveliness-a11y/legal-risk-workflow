# 风控律师工作流（Risk Workflow — DAG 调度器）

## 定位

**阶段主干固定为默认路径，模型可在分支点依据项目状态建议调整；重大节点（尽调启动、报告定稿、交易与投后基线）必须人工审批，机械性确认默认合并进检查点呈报。**

本 Skill 是风控工作流的主调度器，职责：
1. 读项目日志，判断当前阶段与步骤
2. 告知当前步骤的默认动作与产出
3. 在分支点给出可选路径与建议，交用户/审批人决策
4. 不替代任何能力 Skill 的内部逻辑

**全局契约**：全部技能（含本调度器）统一遵守 [CONTRACT.md](./CONTRACT.md)——工作区与数据总线（§1）、Dossier canonical working view + 证据链登记（§2）、执行状态文件（§3）、检查点（§4）、风险编号（§5）、验收契约 AC1-AC5（§6）、外部依赖适配器（§7）、文档产出（§8）、项目日志与启动自检（§9）、版本与兼容（§10）。本文件只描述调度逻辑，凡与契约重复的内容一律引用、不复述。

## 6 阶段总览

| Phase | 名称 | 主技能（默认） | 关键输入 | 关键产出 | 主 CP |
|---|---|---|---|---|---|
| 1 | 项目准备 | dd-prep（调用 qcc-scan / industry-research） | 项目名、BP、公开数据 | 尽调清单、访谈提纲、风险假设、初筛卡 | CP1 尽调启动确认 |
| 2 | 尽调执行 | dd-check T2 → dd-interview 模块 A/B → 补充核查 | 清单、企业材料、访谈转写 | verification_table、纪要、interview_result、pending 清单 | CP2 尽调收口（呈报，结论性缺口时阻断） |
| 3 | 报告撰写 | risk-report | Dossier、核查表、纪要 | 风控报告 + risk_matrix（含条款映射提示） | —（初稿交复核） |
| 4 | 复核 | report-review | 报告初稿 | 复核意见、修订闭环记录 | CP3 报告定稿确认 |
| 5 | 交易文件 | txn-docs | 定稿报告、条款映射 | 条款落实表、保全校验表、覆盖度报告 | CP4 交易与投后基线确认 |
| 6 | 投后跟踪 | post-invest-check（qcc-scan 定期复查） | 法律台账、交割义务 | 台账更新、预警记录 | —（持续性，无终止） |

**业务链**：投资经理侧顺序为 小预审 Go/No-Go → 深度尽调 → 访谈与验证 → 研究更新 → 交易架构 → 大预审 → 投委会 → 投后跟踪；风控侧 Phase 1-6 与之对应。允许回环：复核不通过可回 Phase 2 补充调查或 Phase 3 修订报告；回环时已有产物不覆盖，版本共存标注。

**Phase 3 内部默认顺序**：预检+数据源复查（缓存 >7 天触发 diff）→ 前言与前提 → 基本情况 → 重点问题（核心章节，按风险主题逐项 IRAC）→ 投资方案评估 → 风险总结（编号稳定化）→ 跨章一致性检查。报告按风险主题聚焦生成，减少单次上下文负载。

**各 Phase 进入条件（一句话）**：
- Phase 1：新项目或用户明确启动尽调
- Phase 2：CP1 通过（清单+提纲获批）
- Phase 3：Phase 2 产物齐备（核查表+纪要）且 CP2 收口呈报完成——默认直接进入报告撰写，结论性缺口时经审批人决定（CONTRACT §4.1）
- Phase 4：报告初稿完成且一致性检查无阻断项
- Phase 5：CP3 通过（报告封版）；投委会通过+签约打款后转 Phase 6
- Phase 6：交割后持续运行，可反复调用

## 能力技能清单（10 个，可跨阶段调用）

能力 Skill 不是流水线节点，而是独立能力，同一 Skill 可在多个 Phase 被调用。

| 能力 Skill | 主战场 | 其他可调用 Phase | 独立触发 |
|---|---|---|---|
| dd-prep | Phase 1（4 步各自独立可调） | — | ✅ |
| qcc-scan | Phase 1 | 2 / 3 / 6 | ✅ |
| industry-research | Phase 1 | 2 / 3 | ✅ |
| dd-check | Phase 2（T2 正向匹配） | 1（T1 预扫描）/ 3（T3 增量）/ 4（补充） | ✅ |
| dd-interview | Phase 2（模块 A 纪要 / 模块 B 归纳） | 4（补充访谈） | ✅ |
| risk-report | Phase 3 | 4（修订） | ✅ |
| legal-research | Phase 3（法源核验，risk-report 步骤 5 调用） | 4（定稿复核补验）/ 5（条款依据确认） | ✅ |
| report-review | Phase 4（双层复核） | 3（草稿期轻量自检） | ✅ |
| txn-docs | Phase 5 | — | ✅ |
| post-invest-check | Phase 6 | — | ✅ |

**调用原则：Phase 阶段固定，能力按需调用，报告始终迭代。** 每个步骤的默认动作固定，模型不自行决定跳步；分支点由模型建议、用户决策；报告版本迭代遵循 CONTRACT §8。

## 调度逻辑

### 会话启动

执行 [CONTRACT.md](./CONTRACT.md) §9 的一页启动自检：读日志末尾判步骤 → 核对 Dossier §0 状态 → 按衔接表查上游文件 → 处理 blocked/待办 → 确认主 CP 审批状态。通过后向用户报告：当前 Phase/Step、默认动作、分支点选项（如有）、异常项（如有）。**无异常且无分支点时直接执行默认动作，不等待确认**；存在异常或分支点时停下等待用户决定；涉及主 CP 的按 §4 等待审批。

### 日志即状态源

- `project_log.md` 只追加不删改；分支点决策记一行（路径+依据），主 CP 确认记录格式见 CONTRACT §4。
- 日志与 Dossier 分工：日志记"做了什么、到哪一步"；Dossier 记"事实是什么、来源与确定性"。
- 日志与产物矛盾：以最新产物时间戳为准，追加修正说明。

### 场景判断（会话启动时识别）

| 场景 | 识别信号 | 语义 |
|---|---|---|
| 首轮尽调（标准模式） | 新项目，日志不存在 | 走完整 6 阶段默认路径；按轮次差异化深度（天使 15-20 项精简清单 / 成长期 30-40 项 / Pre-IPO 50+ 项含上市专项） |
| 增量模式 | 已有纪要/核查表，出现新材料、新转写或 pending 清单 | 追加补充、不重做已有产出；核查走 dd-check T3，访谈追加专节；按 CONTRACT §8.1 交付变更摘要（受影响风险编号+等级变化+新增/关闭项） |
| 加急模式 | 用户明确要求压缩周期 | 清单/行业研究降为快速扫描，**复核不降级**；验收契约 AC1-AC5 不豁免 |
| 补充尽调 | report-review 结论为"需补充调查" | 回 Phase 2 补充核查回路，只补目标项，完成后回到报告修订 |

场景结论记入日志一行（场景+依据+执行模式），不设固定字段模板。

## 检查点

4 个主检查点：**CP1** 尽调启动确认 / **CP2** 尽调收口 / **CP3** 报告定稿确认 / **CP4** 交易与投后基线确认。其中 CP1/CP3/CP4 为**人工审批、阻断性**（批准外发与工作范围、接受未决风险并批准定稿、确认交易条件）；CP2 为收口呈报，默认随报告初稿一并交 CP3 审批、不停顿，仅当存在足以改变核心结论的缺口时阻断升级。位置、呈报内容与规则见 [CONTRACT.md](./CONTRACT.md) §4。

技能内部的重要中间判断（风险假设成型、单场纪要完成、报告分析框架等）为子确认：默认并入下一个主 CP 的呈报项一并审批，不单独停顿；仅会改变工作范围或结论方向的判断才单独提出（CONTRACT §4.2）。

## 数据衔接

工作区目录结构、技能间衔接文件与消费关系统一见 [CONTRACT.md](./CONTRACT.md) §1。要点：

## 异常处理

原则：**降级不断流**——外部依赖缺失时按 CONTRACT §7 适配器降级并按 AC5 显式标注「本项未核查，原因：…」，流程继续；禁止以沉默冒充无风险。

| 场景 | 处理 |
|---|---|
| 工商数据源失败/限流 | 用已有缓存；无缓存走手工采集模式（CONTRACT §7.1）；仍不可得 → 标注待核实后推进 |
| 行业研究无结果 | 标注 [推断] 无行业特殊风险，不阻塞 |
| 关键材料缺失 >50% | 按 CP2 结论性缺口处理（CONTRACT §4.1）：标明缺口与影响，由审批人决定补材料、带限制继续或暂缓该项判断 |
| 脚本执行失败 | 跳过脚本，模型手工替代（效率降，不断流） |
| 同一步骤失败 ≥3 次 | **暂停升级人工**：停止重试，向审批人说明错误与建议方案，不自行换路径 |
| 用户要求跳过中间 Phase | 默认路径不可跳过，可加速（合并子确认）；任何偏移记入日志 |
| 用户要求回退 | 允许，追加回退记录；已有产物不覆盖，版本共存 |
| project_log.md 损坏/不可读 | 从 Dossier 与目录产物重建日志骨架，标注 [重建] |
| Dossier 缺失 | 从模板初始化并标注 [重建]；缺失状态下报告不出终稿 |

**安全底线**：对外文档（清单/报告/交易文件）生成前检查不含内部字段（风险等级、核实方式、内部备注）；任何文件外发前必须审批人确认，AI 不得自行发送。

## 风险评级核心原则（全工作流通用）

> **关注风险是否现实发生，是否对上市有实质重大影响，潜在/低影响风险不能过高评级。**
> 权威定义见 risk-report references/ 与 `knowledge-base/reference/risk_classification_framework.md`。每次输出风险矩阵前逐条校验。

| 维度 | 规则 |
|---|---|
| 现实风险 vs 潜在风险 | 潜在风险评级不超过中🟡 |
| 上市影响评估 | 非审核红线事项不应评为高🔴/中高🟠 |
| 常见合规瑕疵 | 未上市企业普遍存在的降级为中低🔵/低🟢 |
| 已整改事项 | 已合规整改完毕的历史问题降级处理 |
| 行业特异性例外 | 医疗（临床试验合规）、半导体（出口管制）、军工（资质有效性）、数据密集型（数据出境）、金融（牌照有效性）、新能源（环保合规）的高频风险不适用自动降级 |

## 知识库维护（数据飞轮）

知识库随项目积累进化，但**项目学习默认写入仓库外的私有知识库**；公共知识库仅接受去除个案信息的通用方法，经独立发布审核后更新。每完成 5 个项目，主动提醒审批人执行知识库审查：
1. **风控发现沉淀**：读近 5 个项目的 risk_matrix，识别新风险模式 → 先写入私有库；其中不含个案信息的通用模式经发布审核后可进入公共沉淀
2. **行业专项检查库**：新行业缺失检查点 → 私有库先行；公共行业库仅收录条件式核查问题（不含个案状态与成套参数）
3. **写作范式**：新案例笔记与现有范式对比 → 新范式先更新私有写作范式库；进入公共 writing_patterns 前去除个案信息并经发布审核
4. **术语表**：新术语 → 更新

审查结果经人确认后写入私有库；拟进入公共库的内容按 [docs/EXCLUSIONS.md](../../docs/EXCLUSIONS.md) 的发布范围规则审核，并同步更新 VERSION.md。

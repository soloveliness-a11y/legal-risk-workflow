# txn-docs — 交易文件风险→条款映射审查

> 遵循 [CONTRACT](../risk-workflow/CONTRACT.md)。本文件只描述映射审查的专业逻辑；数据总线（§1）、Dossier 更新（§2.4）、output 状态文件（§3）、检查点 CP4 审批语义（§4.1）、覆盖度验收 AC2 与跨文档一致性 AC4（§6）、OCR 适配器（§7.2）以契约为准。

## 定位（开源重塑）

**风险→条款映射审查层。** 核心价值：将风控发现的问题精确转化为交易文件中的保护性条款，并验证合同条款覆盖所有已识别的法律风险（CONTRACT §6 AC2）。

- 范本文件未随开源包发布（权属原因，见 `templates/交易文件模板/README.md`）；本技能**不内置条款内容，起草不是主路径**。
- 内置资产是**方法论**：条款分类决策树（`references/clause_mapping_rules.md`）+ 映射规则（`templates/clause_mapping_rules.json`）+ 条款结构说明（`knowledge-base/reference/transaction_clause_library.md`，结构供对照定位条款位置）。
- 条款文本的两个来源：用户已有的交易文件（默认），或用户机构自备范本。

## 触发条件

投决会通过，决策投资。

## 两种工作模式

| 模式 | 适用 | 文本基础 | 交付差异 |
|------|------|---------|---------|
| **模式二：已有文件修订（默认）** | 非领投 / 有前轮文件 / 对方已出具文本 | 用户提供的既有交易文件 | 三件套 + 前轮权利保全校验表 |
| **模式一：自备范本接入** | 首次融资或我方主导文本 | 用户机构任意范本 | 三件套（在范本上做映射填充） |

**模式二核心原则（"增加不删减"）**：在前轮基础上增加而不删减前轮投资人权益；签署完整的股东协议（非补充协议），前轮被完全替代；前轮权利保持不变或按约定升级；前轮条款与本轮需求冲突时，标注冲突点并建议处理方式，交审批人决策。

**模式一要点**：在用户范本完整文本基础上修改填充，不建议从条款库从零组装（一致性问题）；范本未提供时向用户索取，不替用户起草全文。

模式选择与确认属 CONTRACT §4.2 子确认：向用户确认模式（及模式二的前轮文件完整性）后，开始条款映射。落实表确认与文件终稿进入 CP4（交易与投后基线确认，CONTRACT §4.1）。

## 输入

| 字段 | 必填 | 说明 |
|------|------|------|
| investment_decision | ✅ | 投决意见（投资金额、估值、关键条款要求） |
| risk_matrix | ✅ | risk-report 输出，含 `clause_mapping_hints`（条款映射建议，**必读**） |
| report-review_conditions | ✅ | report-review 输出的 conditions（条件事项），必须在交易文件中落实 |
| report-review_comments | ✅ | report-review 输出的复核意见，修改建议须落实 |
| deal_structure | ✅ | 投资经理提供的交易结构方案 |
| target_company | ✅ | 目标公司全称 |
| drafting_mode | ✅ | 模式一（自备范本接入）/ 模式二（已有文件修订） |
| existing_docs | ❌ | 既有交易文件路径（模式二必填：本轮对方文本或前轮文件） |
| cap_table | ❌ | 当前股权结构表 |

> **clause_mapping_hints 桥接**：risk-report 在风险矩阵中为每条风险给出条款映射建议。必须逐项读取，并经条款分类决策树复核归位后再写入落实表——hints 是建议，决策树是准绳。

## 条款映射流程（核心功能）

### 步骤

```
1. 读取 risk_matrix.json（含 clause_mapping_hints）+ report-review 条件事项
2. 逐项过条款分类决策树（references/clause_mapping_rules.md）
   —— 5 类：陈述保证 / 先决条件 / 交割后承诺 / 特殊权利 / 治理条款
   —— 分类存疑的混合场景对照"9 个常见混淆场景"表判断
3. 按文件类型拆分映射：增资协议类 / 股东协议类
4. 生成三件套（条款落实表 / 保全校验表 / 覆盖度报告）。两类适配：**已交割项目**——先决条件类 hints 转换为"申报前整改条件"语义；**合一版协议**（投资人权利并入增资协议单文件，如第九条）——落实表按文件内条款区块拆分映射，不强制增资/股东两表分立
5. 向用户展示映射一览与分类边界问题 → 子确认（CONTRACT §4.2）
6. 确认后在文本基础上填充/修订条款（md 先行，CONTRACT §8）
7. 更新 Dossier §11/§12/§14
```

**分类速记**：先决条件通常不超过 10 项，绝大多数整改事项放交割后承诺；一项风险可映射多个类型（如"资质正在续期" = 陈述保证 + 交割后承诺）。

### 决策树与映射规则（引用，不复制）

完整体系见 [`references/clause_mapping_rules.md`](./references/clause_mapping_rules.md)：条款分类决策树（5 类）、9 个常见混淆场景对照表、增资协议/股东协议映射规则、风控发现→条款类型速查表（12 类）、轮次差异化重点。执行映射、生成落实表时**必须读取**。规则化配置见 [`templates/clause_mapping_rules.json`](../../templates/clause_mapping_rules.json)。

### 条款结构说明（定位用）

条款在文件中的常规位置参照 `knowledge-base/reference/transaction_clause_library.md`（增资协议 14 条 + 附件、股东协议 14 条、股权转让协议 14 条的结构，及各类条款的内容要点）。落实表"文件位置"列按实际文本的条款编号填写，结构说明仅用于快速定位。

实际交易文件组合按投资方式确定：

- 纯增资：增资协议 + 股东协议 + 股东名册 + 出资证明书
- 纯老股转让：股权转让协议 + 股东协议修订 + 股东名册
- 组合方式：投资协议（合一版）或分别签署 + 股东协议 + 股东名册 + 出资证明书

## 核心交付物（三件套）

### 一、条款落实表（按文件拆分，表格格式）

> 每项风控发现必须在两份落实表之一中有对应条款映射，无遗漏。条款类型必须为 5 类之一，落实状态五档：已落实 / 部分落实（条款存在但有留白或覆盖不全）/ 缺口（条款完全缺失，需增补）/ 待确认 / 无法映射（需人工处理）。

**落实表一：增资协议类条款落实表**

| risk_id | 风控发现 | 条款类型 | 分类依据 | 具体条款 | 文件位置 | 落实状态 |
|---------|---------|---------|---------|---------|---------|---------|
| R01 | IDC 牌照续期中 | 陈述保证 | 确认现状（正在续期） | 公司陈述正在申请续期 | 增资协议-附件二 | 已落实 |
| R01 | IDC 牌照续期中 | 交割后承诺 | 未来行动 | 交割后 6 个月内完成续期，逾期创始人兜底 | 增资协议-第五条 | 已落实 |
| R03 | 可转债未清理 | 先决条件 | 交割前必须清理 | 清理完毕并取得债权人确认函 | 增资协议-附件一 | 已落实 |
| R05 | 关联交易不规范 | 治理条款 | 保护性规定 | 关联交易须经投资人批准 | 股东协议-第三条 | 已落实 |

**落实表二：股东协议类条款落实表**

| risk_id | 风控发现 | 条款类型 | 分类依据 | 具体条款 | 文件位置 | 落实状态 |
|---------|---------|---------|---------|---------|---------|---------|
| R08 | 投资人权利保障 | 特殊权利 | 投资人特殊权利条款 | 回购/反稀释/优先清算安排 | 股东协议-第七条 | 待确认 |

每份落实表附**未映射风控发现**清单：`| risk_id | 风控发现 | 无法映射原因 |`，交审批人判断。

### 二、前轮权利保全校验表（模式二必出）

逐一核对前轮投资人每项权利在本轮文件中的对应状态，确保"增加不删减"：

| 前轮权利条款 | 前轮文件位置 | 本轮对应条款 | 保全校验 | 变更说明 | 是否需补充 |
|------------|------------|------------|---------|---------|-----------|
| A 轮投资人回购权（年化 10%） | A 轮股东协议第 X 条 | 本轮股东协议第 Y 条（原文保留） | ✅已保全 / ⚠️部分变更 / ❌未保留 | | 是/否 |

结尾给出结论：前轮权利全部保全 / 存在 X 项需补充保全 + 待处理事项清单。

### 三、覆盖度报告

```
条款覆盖度 = 已映射风控发现数 / 风险矩阵风险总数
校验规则（CONTRACT §6 AC2）：
  1. 每个 risk_id 至少在一份落实表中有 1 条映射
  2. 无法映射的风险 → 列入"未映射风控发现"+ 原因，不得静默丢弃
  3. 覆盖度 <100% → 在报告中标注并说明
```

报告内容：风险总数 / 已映射数 / 未映射数及原因 / 模式二时前轮保全校验结论 / 建议（哪些风险需人工决策处理方式）。

### 谈判要点备忘（附于三件套后）

| 类别 | 内容 |
|------|------|
| 底线条款 | 回购条款不可删减 / 信息披露权不可删减 / 保护性规定核心事项 |
| 可协商条款 | 回购年化利率 / 答复期长短 / 重大资产处置阈值 |

**特殊检查点（三件套之外逐项过）：**
1. 保障条款存续独立性：回购/对赌等保障条款的解除、失效事件不得与义务人自身资本运作节奏（IPO 申报、股改、控股股东重组上市）自动挂钩；确需 IPO 前清理的，同步签署"未过会/撤回即自动恢复"的解除与恢复协议并纳入交付物；
2. 领售权（老股受让项目）：核查受让股权是否受领售权支配、领售触发门槛与估值口径；受让后仍被领售支配的，在落实表标注并建议谈判调整；
3. 抽屉协议排除：确认不存在与公司/原股东单独签署、优于主协议且损害其他投资方的补充安排（存在被认定无效的司法风险）；后轮面对前轮更优回购条件的，拉平回购条件并设兜底回购。

## Dossier 更新

txn-docs 是 Dossier §11（融资历史与投资条款）的**定稿时机**（遵循 CONTRACT §2.4）：

1. **§11**：本轮投资条款摘要 + 前轮保全状态 + 风控条款落实摘要
2. **§12**：标注哪些风险已通过交易条款缓释（✅已缓释）
3. **§14**：交割后义务写入（与 post-invest-check 衔接）
4. **§0 / §15**：元信息与来源索引同步

质量要求：§11 与交易文件终稿一致；§12 缓释状态已标注；§14 含交割后义务清单。

## 输出

output.json 按 CONTRACT §3 最小 schema，可按需追加扩展字段 `drafting_mode`（模式一/模式二）、`coverage`（{风险总数, 已映射数}）、`prior_round_preserved`（模式二：true/false/部分）。

产出文件（`06_txn_docs/`）：交易文件修订稿/填充稿（md 先行，docx 可选）、条款落实表 ×2、前轮权利保全校验表（模式二）、覆盖度报告、谈判要点备忘。

## 前置强制动作：修订态检测

提取任何 docx 条款前，必须先检测 w:ins/w:del 修订痕迹（含未接受修订的文件，纯文本提取会静默漏读全部插入内容）。存在修订时以"接受全部修订后"文本为审查基准，修订态条款加【修订态】标注。此为强制步骤，不依赖异常表触发。

## 异常与边界处理

| 场景 | 触发条件 | 处理动作 |
|------|---------|---------|
| 前轮文件不完整 | 模式二缺少关键条款（回购/反稀释/优先权） | 禁止推进模式二；向审批人列出缺失项，等待补全或切换模式一 |
| **既有文件含未接受修订（红线稿）** | 纯文本提取会**静默漏读全部插入内容**（w:ins），审查结论系统性失真 | 解析 docx 的 w:ins/w:del 修订痕迹，以"接受全部修订后"的文本为审查基准，保留修订态条款加【修订态】标注，并在落实表标注"该条款仅以未接受修订存在，须在签约流程中确保接受" |
| 既有文件为扫描件 | OCR 前无法直接读取 | 遵循 CONTRACT §7.2：先试读，扫描件才 OCR；**交易文件属敏感类别，禁止上传外部 OCR**（本地 OCR 或人工比对）；提取的条款逐条与原文核对，遗漏一条投资人权利条款可能导致重大法律风险 |
| 前轮权利冲突 | 本轮需求与前轮投资人权利矛盾 | 标注冲突点 + 建议方案，审批人决策 |
| 风控发现无法映射 | 决策树无法归类 | 记入"未映射风控发现"，交审批人判断 |
| 范本/文件缺失 | 模式一未提供范本 / 模式二未提供既有文件 | 向用户索取；不替用户从零起草全文 |
| 投资方式不确定 | 未明确纯增资/老股转让/组合 | 先确认投资方式，再启动映射 |

# report-review — 风控复核与大预审支持

> 遵循 [CONTRACT](../risk-workflow/CONTRACT.md)。本文件只描述复核的专业逻辑；数据总线（§1）、Dossier 更新（§2.4）、output 状态文件（§3）、检查点与审批语义（§4）、验收契约 AC3/AC4（§6）以契约为准。

## 触发条件与路径选择

风控报告初稿完成，提交复核。

| 报告版本 | 复核路径 |
|---------|---------|
| V1.0+ | 完整复核（第一层 7 项 + 第二层 6 维） |
| V0.xd | **首次复核走完整双层**（初稿第一次进复核时）；仅同一版本内的迭代再入复核时用轻量自检（3 项，见"版本管理规则"节） |

## 输入

| 字段 | 必填 | 说明 |
|------|------|------|
| risk-report | ✅ | 风控报告初稿（`04_risk_report/` 下文件或全文） |
| risk_matrix | ✅ | 风险矩阵（risk-report 输出） |
| report_conclusion | ✅ | 风控结论（通过/有条件通过/不建议） |
| qcc_cache | ❌ | 工商数据缓存（交叉验证，schema 见 CONTRACT §7.1） |
| legal_authority | ❌ | 法源核验记录（legal-research 输出 `legal_authority.json`，authority audit 交叉验证用；**V0.xd 草稿**复核时缺失则法条引用标"待核验"（WARN），**CP3/V1.0d 定稿**复核时缺失即 FAIL、退回补验） |
| evidence_registry | ❌ | 证据链登记（CONTRACT §2.5；核对报告中冲突事实的表述是否与未裁决 contradiction_group 一致） |
| company_response | ❌ | 公司对风险事项的反馈/承诺函 |
| historical_cases | ❌ | 历史同类项目风险参照（案例学习笔记——可选私有库，开源包不含；缺失时用行业模块+风控发现沉淀替代对照） |
| prior_report | ❌ | 前轮风控报告（对比跟进） |

## 双层复核架构

### 第一层：AI 自查（文本与逻辑层，7 项）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 1 | 逻辑结构与格式 | 风险分类和层次清晰；8 章结构完整、引用标注规范、落款齐全；上下文无逻辑冲突、重复或低级错误 |
| 2 | 表述与语气 | 表述专业、符合投委会审阅习惯；风控提示语气与风险等级严格匹配 |
| 3 | 合规与法律依据 | 结合法律法规、IPO 审核要求及监管案例指出需补充/强化的风险提示；法律依据条件化：涉及法律义务、监管要求、上市规则或其他规范性判断的风险，应提供可核验依据（法条/规则/监管口径，注意时效复核）；纯交易执行、事实核查、商业依赖、保障机制或退出不确定性类风险，**不得为满足格式强行配置法律依据**；**Authority audit（按报告版本分级）**：核对报告法条引用与 `legal_authority.json` 的一致性（risk_matrix `legal_propositions` ↔ authority_record proposition_id 一一对应；orphan L 编号、非 effective 状态的 L 参照 legal-research 下游规则拦截）。**V0.xd 草稿**——未经核验的法条引用标"待核验"（WARN），可继续迭代；**CP3 / V1.0d 定稿**——涉及法律义务、监管要求、上市规则的实质性法律命题没有有效 authority chain（effective 状态的 authority_record）的，**判 FAIL、不得通过 CP3**，退回补验。模型自行检索到官方源的法条同样必须正规化为 authority_record 落盘，禁止以"自行检索"为由绕过 registry |
| 4 | 风险等级准确性 | 结论简洁有力；等级与事实状态分离呈现（影响定级、证据定确定性，"高影响×低确定性"不混同为已确认事实）；评级依据（影响×可能性×可缓释）逐项可查；无机械降级标签——"尚未实质化""非审核红线""行业常见""已整改"不是独立的降级或封顶理由，只作为影响评估的输入；证据不足处应暂缓定级并列出所需信息而非压低等级 |
| 5 | 重大判断质量（五问视角） | 按 report 写作主线（SKILL §7 Ch.5）的产出核对，中🟡及以上逐项过**五问**——①发现什么（事实/公司陈述/推断分层，不混同）②依据（可定位材料；未裁决冲突并列呈现、已裁决按裁决结果表述并保留依据）③为什么重要（对交易/估值/履约/治理/退出的具体影响）④建议怎么办（下一步动作或交易条件）⑤什么新信息会改变判断（仅重大不确定性必答，事实已查清的不强制）。查内容质量而非格式，自然段合并回答即可；任一问的缺失影响理解、判断可靠性或行动安排时退回。**底线核对**：无项目事实支撑的通用提示填充正文、未提供材料写成违法违规、"未发现"写成"已排除"等把未知写成确定的问题，诊断为该事项的分析未完成（缺事实整理、义务识别、履行比较或时间线中的某步），退回时指出应补的分析环节，不是让作者改措辞。**规则复述检查**：报告正文出现技能规则原句的，检查该处是否提供了项目分析（材料状态、判断范围、后续工作）；仅复述规则不算通过 |
| 6 | 建议可操作性 | 每条建议有具体措施、责任方、时间节点 |
| 7 | 风险矩阵完整性 | ① 矩阵汇总表与正文各风险点逐条对应；② 等级分布诊断：如风险等级出现显著集中（多数同级），复核是否存在统一的评级偏高/偏低偏差（如评级通胀/通缩），并抽查 3 项的定级依据；**不得为满足任何预设分布比例调整评级**——评级只依据单风险的现实性/可缓释性/上市影响判断；③ 风控发现沉淀 7 大主题逐项对照 |

**三层复核口径（第一层自查按此对齐）：** ①实质四性——内容完整性、重要问题评价准确性、尽调完备性、意见充分性（对照风险假设与小预审关注点评估是否达上会标准）；②形式覆盖——小预审重点问题是否全部覆盖；③事实一致——报告与投资建议书共同涉及的事实/数据冲突逐项核对，合理口径差异注明并汇报；读取 `evidence_registry.json` 中**未裁决的 contradiction_group**，核对报告对相应事实是否保持 ⚠️ 双源并列或条件化表述——未裁决冲突在报告中静默选边的，该项不过。案例引用可溯性：复核中引用的对照案例须可回溯知识库或公开来源，禁止凭印象引注。

**输出**：优化完善后的法律风控报告（逐项标注修改建议及理由）。

### 第二层：整体风险判断复核（宏观把控，6 维）

| # | 复核维度 | 检查要点 |
|---|---------|---------|
| 1 | 重大风险遗漏 | 对照项目实际风险框架无重大遗漏或低估；报告事实与数据缓存（工商/高管画像）无矛盾，"无同业竞争"等声明有据可查；有前轮报告的项目，前轮问题均有跟进结论 |
| 2 | 重点突出性 | 突出重点风险，而非面面俱到缺乏焦点 |
| 3 | 风控措施可行性 | 提出的措施切实可行，有落地路径 |
| 4 | 整体风险判断 | 整体判断合理，结论与风险分析一致；股权/财务等数据引用遵循数据源优先级规则；区分"风险揭示失误"与"揭示充分但投资未跟进/节奏错配"——后者属决策与节奏问题，不应倒逼报告改写 |
| 5 | 同类案例对照 | 与案例学习笔记中的历史同类项目对比：风险类型分布是否偏离行业常态、同类风险的处理结论是否一致、本报告结论是否过于乐观/悲观。私有案例库缺失时，退化为行业检查库+风控发现沉淀的主题对照。风险等级与 evidence confidence 双轴校验：检查报告是否将"高影响×低确定性"的假设性风险错误呈现为"已确认的高风险事实"（等级与确定性分离） |
| 6 | 风险收益平衡（ROI 视角） | 重大风险对预期投资回报的影响程度、缓释措施成本与预期收益是否匹配、退出路径（IPO/并购/回购）受风险影响程度 |

维度 5 须给出**具体案例引用**（示例："参照历史同类项目，同类代持风险在 Pre-A 轮均评为中🟡，本报告评级是否一致"）。维度 6 量化分级：有完整财务输入（模型/估值/时间表）→ 可量化（IRR/回收率/稀释测算）；有部分输入 → 做敏感性与区间分析；无可靠输入 → 只描述影响机制与关键敏感变量，**不得生成 IRR、估值折让、退出概率或损失金额等任何自补数值**。

**输出**：整体风险判断复核意见（宏观层面的挑战和建议）。

## 处理流程

```
1. 第一层 AI 自查 → 优化报告（标注修改建议及理由）
2. 第二层整体风险判断复核 → 宏观挑战和建议
3. 风险判断校准 → 对照历史同类项目校准等级
   （重点：等级是否与影响×可能性×可缓释的分析相称；有无机械封顶降级或把未知写成确定）
4. 大预审汇报材料生成（如需）
5. 补充资料闭环（如需）
6. 更新 Dossier §12（等级调整同步写入，见下"Dossier 更新"）
```

## 复核结论与 CP3 语义

复核结论属 CONTRACT §4.1 **CP3（报告定稿确认）**范畴：两层复核完成、输出结论后，向审批人呈报复核结论 + 关键修改意见 Top 5 + 风险等级校准建议 + **关键待核实事项**（CP2 收口并入项：pending_materials 与 pending_items 合并视图，按对结论影响排序，CONTRACT §8.1）。以下情况必须等待审批人确认：

- 结论为"不通过"→ 由审批人决定是否触发按需增量核查（见下方协议）
- 结论为"有条件通过"→ 由审批人确认条件事项是否可接受
- 风险等级调整超过 2 项 → 由审批人确认调整是否合理

确认记录按 CONTRACT §4.1 写入 `project_log.md` 一行，不设签名模板。

## 大预审材料

### 大预审风险摘要（一页纸）

输出：`大预审风险摘要_{项目名}_{日期}.md`

```
{公司名} 大预审风险摘要
投资方案：{金额}/{估值}/{持股比例}
风控结论：{通过/有条件通过/不建议}

风险矩阵（精简版）：
| 大类 | 风险点 | 等级 | 缓释状态 |

关键风险提示（Top 3）：
1. {最高等级风险点概述}
2. {次高等级风险点概述}
3. {投委会关注焦点}

待决事项：{需投委会决策的关键问题}
```

### 投委会 Q&A 预案

输出：`投委会QA预案_{项目名}_{日期}.md`

预判投委会委员可能提出的 10-15 个问题，来源维度：
- 风险等级最高的 2-3 个事项（深挖型提问）
- 行业特有风险（专业性提问）
- 投资方案与风控发现的对齐度（决策型提问）
- 前轮问题跟进情况（对比型提问）

格式：`Q: {问题} → A: {建议回答（含数据支撑）} → 依据：{报告章节引用}`

### 意见跟踪表

大预审后记录委员意见用于材料完善：字段 = 委员意见 / 是否采纳 / 落实措施 / 完成状态。

**大预审后收口（四项核对 + checklist 收口）：** ①披露事项是否适合投委会披露；②数据/事实与投资建议书一致；③大预审新提出的问题已更新进报告；④会后新发生事项补充审查。以 checklist/表格逐项填列补正情况交复核人核对；复核人剔除过于主观/个人/极端的观点后形成投委会版；对外发 LP/引导基金的版本须再脱敏并经内部审核后方可发出。

## 补充资料闭环

复核后仍存在的问题 → 生成补充资料清单 → 公司补充后**轻量级闭环复核**：

- 不重新走完整复核流程
- 仅验证补充资料涉及的风险点：资料是否充分、风险等级是否调整、结论是否变更
- 输出：补充资料闭环确认表（逐项标注"已解决/需进一步/无法解决"）

**闭环升级标准**（任一触发即回到完整复核）：

- 补充资料涉及 ≥3 个风险点等级调整
- 补充资料揭示新的风险类型
- 补充资料导致风控结论可能变化

## 版本管理规则

### 版本升级流程

| 阶段 | 版本号 | 存放位置 |
|------|--------|---------|
| risk-report 初次输出 | V0.xd | `04_risk_report/`（历史封版，review 后严禁修改） |
| report-review 复核后 | V0.(x+1)d | `05_report_review/`（每次复核自增，不覆盖 04 原版） |
| 人工精校后 | V1.0d | `05_report_review/`（最终拟定稿） |

### 核心规则

1. 复核后版本号自增：V0.3d → V0.4d
2. 底稿版 + 投委会版在 `05_report_review/` 中同步维护，版本号一致
3. 复核后如有风险等级调整，更新版 risk_matrix.json 存入 `05_report_review/`（与 04 原版并存），report_version 字段同步更新
4. 人工精校版 docx 转 markdown 后存入 `05_report_review/`，命名 `{项目名}_法律风控报告_拟定稿_V1.0d.md`

### 清单格式复核适配（天使/早期项目）

复核对象为核查清单格式（非 8 章报告）时：①"8 章结构"按清单三段制式（前提声明+总表+分项+结论+落款）等价校验；②IRAC 按"核查事实+风控提示"双段等价校验；③法规引用按天使口径条件化适用（不强配法条）、等级分布不设比例配额（显著集中时按诊断规则复核并声明）；④大预审材料仅当审批人明示需要时生成。

**矩阵规模偏离**（如二轮项目超经验区间）可在报告中声明偏离理由后放行（对齐天使模式"声明偏离"条款）。

### V0.xd 轻量自检

迭代版（V0.1d/V0.2d/…）不走完整复核，仅 3 项轻量自检：

| # | 自检项 | 标准 | 不通过时处理 |
|---|--------|------|------------|
| 1 | 资料覆盖度 | pending_materials.json 中 status=resolved 的项，报告对应章节已更新 | 标注遗漏项，提醒 risk-report 补充 |
| 2 | 风险等级漂移 | 新资料导致的等级变化是否合理（遵循五级分类规则） | 向用户报告变化，确认后更新 |
| 3 | 一致性 | 同一事实（数据/金额/比例）在不同章节表述一致 | 修正不一致处 |

**流转**：继续迭代（pending 项仍多）→ 转定稿（pending 清零/用户确认）→ 需人工确认（≥2 项等级调整）。

## 人工精校闭环（人机学习回路）

AI 完成复核+微调后，风控人员（审批人）通常人工精校 Word 文档。精校完成后的标准操作：

1. **接收精校版 docx**，转 markdown 后与 AI 版 diff，逐项识别修改
2. **分类处理**：
   - 措辞调整 → 学习沉淀到**私有知识库**的写作范式库（公共 `writing_patterns.md` 仅接受去除个案信息的通用方法，经发布审核后更新）
   - 结构变更 → 更新对应技能的格式规范
   - 事实修正 → 更新 workspace 内报告文件（md + risk_matrix.json）
   - 新风险发现/等级调整 → 更新 risk_matrix.json
3. **保存精校版**为正式拟定稿（`{项目名}_精校版.docx`）
4. **同步 Dossier**：§0 版本记录、§12 风险信号（如有调整）
5. **系统性教训**沉淀到私有知识库；其中不含个案信息的通用模式经发布审核后可进入公共风控发现沉淀

精校差异分析要点：

| 差异类型 | 处理方式 | 知识沉淀去向 |
|---------|---------|------------|
| 措辞力度调整 | 记录 AI→精校的措辞变化 | 私有写作范式库（公共库经审核） |
| 信息增删 | 确认哪些信息应删/补 | 私有案例库 |
| 结构重排 | 确认新结构是否更优 | 私有写作范式库（公共库经审核） |
| 表格简化 | 记录可精简的表格内容 | 私有写作范式库（公共库经审核） |
| 风险等级调整 | 更新 risk_matrix.json | 私有发现库（公共沉淀经审核） |

## 按需增量核查协议

复核结论"不通过"时，按需调用 dd-check / dd-interview 增量核查。

### 问题类型分类

| 类型 | 描述 | 回退目标 |
|------|------|---------|
| A 类 | 书面资料缺失/不充分 | dd-check（增量核查） |
| B 类 | 访谈信息不完整/矛盾 | dd-interview（增量纪要） |
| C 类 | A+B 混合 | 同时回退 dd-check + dd-interview |

### review_findings.json（结论"不通过"时必须产出）

作为增量核查的结构化输入，最小结构：

```json
{
  "review_date": "YYYY-MM-DD",
  "review_result": "不通过",
  "supplement_requirements": [
    {
      "id": "SR-001",
      "problem_type": "A/B/C",
      "description": "具体问题描述",
      "target_skill": "dd-check / dd-interview",
      "required_action": "补充XX资料 / 补充访谈XX问题",
      "priority": "高/中",
      "related_risk_ids": ["R03"]
    }
  ]
}
```

保存：`05_report_review/review_findings_{date}.json`

### 修订后复核规则

| 修订级别 | 定义 | 复核方式 |
|---------|------|---------|
| V1.x 修订 | 个别章节调整（≤2 章），风险等级未变 | 轻量确认（覆盖度/等级漂移/一致性 3 项） |
| V2.0 升级 | 多章节重大调整（≥3 章）或有等级变化 | 完整复核 |

### 终止条件

增量核查循环最多 **3 轮**。3 轮后仍不通过：输出"增量核查终止建议" + 仍未解决的核心问题 → 由用户决定 (a) 接受现有风险出报告 (b) 人工介入。

## Dossier 更新

report-review 是 Dossier §12（风险信号）的**校准时机**（遵循 CONTRACT §2.4）：

1. **校准 §12**：等级上调/下调同步更新；新增遗漏风险追加；误判移除；校准动作写入 project_log.md
2. **§14 待办**：复核修改意见需后续跟进的写入
3. **§0 / §15**：元信息与来源索引同步（新增"风控复核"条目）

校准后质量要求：§12 与复核后 risk_matrix 一致；等级调整后章节间一致性已核对（冲突按 CONTRACT §2.4 标注 ⚠️ 并登记 §12 待核实）。

## 条件分支

| 结论 | 后续动作 |
|------|---------|
| 通过 | → 大预审汇报 → 投决 → txn-docs |
| 有条件通过 | → 落实条件事项 → 大预审汇报 → 投决 → txn-docs |
| 不通过 | → 按需增量核查协议 |
| 项目终止 | → 输出终止备忘录 → 归档 → 流程结束 |

衔接：输入 ← risk-report 输出；补充资料闭环 ← 公司反馈 → 更新报告 → **直接复核**（不回撰写环节）。

## 输出

output.json 按 CONTRACT §3 最小 schema（skill / version / project / date / status / outputs），可按需追加 `review_result`（通过/有条件通过/不通过/项目终止）与 `review_layer`（V0.xd 轻量/V1.0 标准）扩展字段。

产出文件：优化后报告（md 先行，docx 可选，遵循 CONTRACT §8）、复核意见 `review_comments_{版本}.md`、大预审材料、review_findings.json（不通过时）。

## 异常与边界处理

| 场景 | 触发条件 | 处理动作 |
|------|---------|---------|
| 报告严重缺陷 | 第一层自查发现 ≥3 项核心问题（事实错误/逻辑矛盾/遗漏） | 回到报告撰写环节修改对应章节，不推进第二层复核 |
| 整体风险判断复核无结论 | 宏观判断模糊，无法形成明确意见 | 标注 `📌需审批人判断`，提供备选方案供决策 |
| 补充资料未到 | 结论"条件通过"但补充资料迟迟未到 | 标注 `⏳等待补充资料`，阶段性封版 |
